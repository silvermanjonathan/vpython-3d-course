A function that returns a planet, a speed that lives on the planet itself, a list of planets turned by one loop, a moon with two motions, and a slider that runs time

Length 90 minutes Ages 10 to 11 New 7 items

What is new today

a function that returns an object, an attribute you give an object, planet.speed and planet.turned, a moon with two rotates, a slider that sets a number on an object, label, scene.camera.follow from a key.

Deliberately re-used: Session 2: a function that makes objects, a list of parts. Session 4: rotate with origin, the degrees counter.

Chunk 2 is the idea the rest of the course leans on: earth.speed = 2 makes a new attribute, and any function that can see the earth can read or change it. This is how the course shares a number between a bound function and the loop without a global. Spend the time on it.

Opener · 10 minutes

Retrieval: rotate, origin, and lists

Paper first.

Question: What is the difference between moon.rotate(angle=radians(10), axis=vec(0, 1, 0)) and the same line with origin=planet.pos added?

Without origin, the moon turns around its own middle, which for a sphere changes nothing you can see. With origin, it moves in a circle around the planet, staying the same distance from it.

Question: A loop adds 3 to a counter on every pass and a gate checks for 360. What does the gate detect, and why does the body of the gate set the counter back to 0?

It detects one full turn. Setting the counter back to 0 starts counting the next turn, so the gate opens again 120 passes later. Without the reset the counter passes 360 and never equals it again.

Question: Three parts are in a list and a loop adds vec(0, 0, -3) to each one's pos. What happens to the distances between the parts?

Nothing. Every part moves by the same vector, so the model moves in one piece.

Chunk 1 of 6

A function that returns the planet it made

Session 2's functions made objects and kept no name for them. This one returns the sphere it makes, so the caller can keep it: earth = make_planet(5, 0.4, color.blue). After that line, earth is the sphere and can be moved, recoloured, or rotated like any other.

Without the return line, earth would be None, and earth.pos would stop the program with an error.

from vpython import *

sun = sphere(pos=vec(0, 0, 0), radius=1.2, color=color.yellow)

def make_planet(distance, size, colour):
    p = sphere(pos=vec(distance, 0, 0), radius=size, color=colour)
    return p

earth = make_planet(5, 0.4, color.blue)
mars = make_planet(7, 0.3, color.red)
print("earth is at", earth.pos, "with radius", earth.radius)
print("mars is at", mars.pos, "with radius", mars.radius)

Predict: What does earth hold after its line runs? And if the return p line were deleted, what would earth hold, and what would happen on the first print line?

What it actually prints (run without a browser)

earth is at <5, 0, 0> with radius 0.4
mars is at <7, 0, 0> with radius 0.3

earth holds the sphere that the function made, 5 from the sun with radius 0.4, and the print line reads its pos and radius.

Without the return line the function still makes the sphere, and it still appears in the tab, but the function gives nothing back, so earth holds None. The print line then asks None for its pos and the program stops with AttributeError: 'NoneType' object has no attribute 'pos', the same error as a click on empty space in session 1.

Chunk 2 of 6

An object can carry a number you give it

pos, radius and color are attributes VPython gave the sphere. You can give it more. earth.speed = 2 makes an attribute called speed on the earth and puts 2 in it. From then on earth.speed reads it, and any line that can see earth can change it.

The number belongs to the object. Mars has its own speed, which can be different, and a loop over planets can ask each one for its own.

Reading an attribute you have not given yet is an error, and the last line shows which one.

from vpython import *

sun = sphere(pos=vec(0, 0, 0), radius=1.2, color=color.yellow)
earth = sphere(pos=vec(5, 0, 0), radius=0.4, color=color.blue)
earth.speed = 3
earth.name = "Earth"
mars = sphere(pos=vec(7, 0, 0), radius=0.3, color=color.red)
mars.speed = 2
mars.name = "Mars"

print(earth.name, "turns", earth.speed, "degrees per pass")
print(mars.name, "turns", mars.speed, "degrees per pass")
print("the earth's radius is", earth.radius, "and its speed is", earth.speed)
print("mars has a year counter:", mars.year)

Predict: Which of the earth's attributes in this program came from VPython, and which did the program give it? The last line reads mars.year, which nothing has set. What happens?

What it actually prints (run without a browser)

Earth turns 3 degrees per pass
Mars turns 2 degrees per pass
the earth's radius is 0.4 and its speed is 3
Traceback (most recent call last):
  File "Jonathan_vpython05.py", line 14, in <module>
    print("mars has a year counter:", mars.year)
                                      ^^^^^^^^^
AttributeError: 'sphere' object has no attribute 'year'

radius, pos and color came from VPython. speed and name were given by the program, with an assignment each.

The last line stops the program: AttributeError: 'sphere' object has no attribute 'year'. An attribute exists from the moment something is assigned to it, and not before. The three lines above it printed first, so the output box shows them and then the error.

Chunk 3 of 6

One loop turns every planet by its own speed

The function now takes a name and a speed and puts both on the planet, plus a turned counter starting at 0. The planets go in a list. One loop rotates each planet around the sun by its own speed and adds that speed to its own counter, and a gate on 360 says when each planet finishes a year.

from vpython import *

sun = sphere(pos=vec(0, 0, 0), radius=1.2, color=color.yellow)

def make_planet(name, distance, size, colour, speed):
    p = sphere(pos=vec(distance, 0, 0), radius=size, color=colour)
    p.name = name
    p.speed = speed
    p.turned = 0
    return p

planets = []
planets.append(make_planet("Mercury", 3, 0.2, color.gray(0.6), 6))
planets.append(make_planet("Earth", 5, 0.4, color.blue, 3))
planets.append(make_planet("Mars", 7, 0.3, color.red, 2))
passes = 0

while True:
    rate(30)
    passes = passes + 1

    for p in planets:
        p.rotate(angle=radians(p.speed), axis=vec(0, 1, 0), origin=sun.pos)
        p.turned = p.turned + p.speed
        if p.turned == 360:
            print(p.name, "finished a year on pass", passes)
            p.turned = 0

Predict: Mercury turns 6 degrees per pass, Earth 3, and Mars 2. Which planet finishes a year first, and on which pass? How many Mercury years fit in one Mars year?

What it actually prints (run without a browser, quit after 180 passes of the loop)

Mercury finished a year on pass 60
Mercury finished a year on pass 120
Earth finished a year on pass 120
Mercury finished a year on pass 180
Mars finished a year on pass 180

Mercury first, on pass 60: 360 divided by 6. Earth finishes on pass 120 and Mars on pass 180.

Three Mercury years fit in one Mars year: Mercury finishes on passes 60, 120 and 180, and Mars finishes once, on 180. The output box shows that order. Each planet keeps its own count in its own turned, which is why one loop can serve all three.

Chunk 4 of 6

A moon has two motions

A moon goes around the earth, and the earth goes around the sun, so the moon has to do both. Two rotate lines: one around the sun by the earth's speed, so the moon keeps up with the earth, and one around the earth by its own speed.

from vpython import *

sun = sphere(pos=vec(0, 0, 0), radius=1.2, color=color.yellow)
earth = sphere(pos=vec(5, 0, 0), radius=0.4, color=color.blue)
moon = sphere(pos=vec(5.8, 0, 0), radius=0.1, color=color.white)
passes = 0

while True:
    rate(30)
    passes = passes + 1

    earth.rotate(angle=radians(3), axis=vec(0, 1, 0), origin=sun.pos)
    moon.rotate(angle=radians(3), axis=vec(0, 1, 0), origin=sun.pos)
    moon.rotate(angle=radians(12), axis=vec(0, 1, 0), origin=earth.pos)

    if passes in [10, 60, 120]:
        print("pass", passes, "  moon to earth", round(mag(moon.pos - earth.pos), 2),
              "  earth to sun", round(mag(earth.pos - sun.pos), 2))

Predict: The moon starts 0.8 from the earth. After 120 passes, is it still 0.8 from the earth? What would happen to that distance if the first moon.rotate line, the one around the sun, were deleted?

What it actually prints (run without a browser, quit after 120 passes of the loop)

pass 10   moon to earth 0.8   earth to sun 5.0
pass 60   moon to earth 0.8   earth to sun 5.0
pass 120   moon to earth 0.8   earth to sun 5.0

Still 0.8, on every line, and the earth is still 5.0 from the sun. The first moon line moves the moon along with the earth, and the second swings it around the earth, so the moon stays with the earth and circles it.

Without the first moon line, the moon would only turn around wherever the earth is on that pass, by 12 degrees, while the earth moves on without it. The distance would drift, growing and shrinking, and the moon would wander off its circle. Delete the line and watch; then put it back.

Chunk 5 of 6

A slider sets a number on the sun, and the loop reads it

The slider's function and the loop need to share one number: how fast time runs. Put it on the sun: sun.factor. The slider's function assigns it, and the loop multiplies every speed by it. Anything that can see the sun can see the number.

At 0 everything stops, but the loop keeps running, so moving the slider again starts things up.

from vpython import *

sun = sphere(pos=vec(0, 0, 0), radius=1.2, color=color.yellow)
sun.factor = 1

def set_time(s):
    sun.factor = s.value
    print("time now runs", sun.factor, "times as fast")

scene.append_to_caption("Time: ")
slider(min=0, max=4, value=1, step=0.5, bind=set_time)

mercury = sphere(pos=vec(3, 0, 0), radius=0.2, color=color.gray(0.6))
mercury.turned = 0
passes = 0

while True:
    rate(30)
    passes = passes + 1

    mercury.rotate(angle=radians(6 * sun.factor), axis=vec(0, 1, 0), origin=sun.pos)
    mercury.turned = mercury.turned + 6 * sun.factor

    if mercury.turned >= 360:
        print("Mercury finished a year on pass", passes)
        mercury.turned = mercury.turned - 360

Predict: The slider is moved to 2 on pass 30, and to 0 on pass 80. Without the slider, Mercury's first year would end on pass 60. When does it end now? And what does Mercury do after pass 80?

What it actually prints (run without a browser, quit after 120 passes of the loop)

time now runs 2 times as fast
Mercury finished a year on pass 45
Mercury finished a year on pass 75
time now runs 0 times as fast

Fed in by the build script: the widget bound to set_time set to 2 on pass 30, the widget bound to set_time set to 0 on pass 80.

The first year ends on pass 45. By pass 30 Mercury has turned 180 degrees at 6 per pass. From then on it turns 12 per pass, so the remaining 180 take 15 passes. The second year ends on pass 75, 30 passes later.

After pass 80 Mercury stops: 6 times 0 is 0, so the rotate turns it by nothing and the counter stops growing. The loop is still running, and the output box shows no more years, because the slider was never moved again.

Chunk 6 of 6

A label that follows, and a key that picks what the camera follows

A label is flat text that floats in the scene at a pos. Give the earth its label as an attribute, earth.tag, and move the label to the earth's pos on every pass, because rotate moves the earth and nothing else moves the label.

A keydown function can choose what the camera follows: e for the earth, s for the sun.

from vpython import *

scene.caption = "Click the scene, then press e to follow the Earth or s for the Sun."
sun = sphere(pos=vec(0, 0, 0), radius=1.2, color=color.yellow)
earth = sphere(pos=vec(5, 0, 0), radius=0.4, color=color.blue)
earth.tag = label(pos=earth.pos, text="Earth", height=14, box=False, yoffset=20)

def pick_view(evt):
    if evt.key == "e":
        scene.camera.follow(earth)
        print("the camera follows the Earth")
    if evt.key == "s":
        scene.camera.follow(sun)
        print("the camera follows the Sun")

scene.bind("keydown", pick_view)
passes = 0

while True:
    rate(30)
    passes = passes + 1
    earth.rotate(angle=radians(3), axis=vec(0, 1, 0), origin=sun.pos)
    earth.tag.pos = earth.pos

    if passes in [20, 40]:
        print("pass", passes, "  label at x =", round(earth.tag.pos.x, 2), " z =", round(earth.tag.pos.z, 2),
              "  earth at x =", round(earth.pos.x, 2), " z =", round(earth.pos.z, 2))

Predict: The label is a separate object from the earth. Why does the loop need the line earth.tag.pos = earth.pos? What would you see without it?

What it actually prints (run without a browser, quit after 40 passes of the loop)

the camera follows the Earth
pass 20   label at x = 2.5  z = -4.33   earth at x = 2.5  z = -4.33
the camera follows the Sun
pass 40   label at x = -2.5  z = -4.33   earth at x = -2.5  z = -4.33

Fed in by the build script: the e key pressed on pass 10, the s key pressed on pass 30.

Because rotate moves the earth and nothing moves the label. The line copies the earth's new pos to the label on every pass, so the output box shows the label and the earth at the same x and z on passes 20 and 40.

Without it the label would stay where the earth started, at x = 5, and the word Earth would float over empty space while the planet went round without it. The e and s keys only change what the camera follows; they do not move anything.

Hinge question · reaches back to session 1

Before you build

Question: From session 1: a student makes the sun with radius=2 and Mercury with distance=1. What do they see in the tab, and which one number do they change?

Nothing, or a grey bump on the sun. Mercury's pos is 1 from the sun's middle and the sun's radius is 2, so Mercury is inside the sun. pos is the middle of a sphere, and a sphere reaches one radius out from it in every direction.

Change Mercury's distance to something bigger than the sun's radius plus Mercury's own radius, 3 or more, so the two spheres do not overlap.

Build · 20 minutes

Build: the solar system

A sun in the middle and at least four planets going around it, each with its own name, distance, size, colour and speed, made by one function and turned by one loop. One planet has a moon. Every planet wears its name on a label that follows it. A slider under the scene runs time faster or slower, and the number keys choose which planet the camera follows. A line of text under the scene counts the Earth's years.

  1. Start from the card below: make_planet with the label as an attribute, and the loop that turns every planet and moves every label.
  2. Make four planets with different distances and speeds. Keep the distances at least 1 apart so no two overlap.
  3. Add the moon from chunk 4 to the second planet, with both rotate lines inside the loop.
  4. Add the time slider from chunk 5, with sun.factor multiplied into every rotate angle and every counter.
  5. Add a keydown function: the keys 1 to 4 call scene.camera.follow on planets[0] to planets[3], and 0 follows the sun.

A planet that carries its own label

The function makes the planet, puts the name, speed and counter on it, and makes a label that it also puts on the planet, as p.tag. The loop then has everything it needs from the planet itself.

from vpython import *

sun = sphere(pos=vec(0, 0, 0), radius=1.2, color=color.yellow)

def make_planet(name, distance, size, colour, speed):
    p = sphere(pos=vec(distance, 0, 0), radius=size, color=colour)
    p.name = name
    p.speed = speed
    p.turned = 0
    p.tag = label(pos=p.pos, text=name, height=12, box=False, yoffset=16)
    return p

planets = []
planets.append(make_planet("Mercury", 3, 0.2, color.gray(0.6), 6))
planets.append(make_planet("Venus", 4, 0.35, color.orange, 4))
passes = 0

while True:
    rate(30)
    passes = passes + 1

    for p in planets:
        p.rotate(angle=radians(p.speed), axis=vec(0, 1, 0), origin=sun.pos)
        p.tag.pos = p.pos
        p.turned = p.turned + p.speed
        if p.turned == 360:
            print(p.name, "finished a year on pass", passes, "  its label is at x =", round(p.tag.pos.x, 2))
            p.turned = 0

Predict: Venus turns 4 degrees per pass. On which pass does it finish a year? Where is its label on that pass?

What it actually prints (run without a browser, quit after 90 passes of the loop)

Mercury finished a year on pass 60   its label is at x = 3.0
Venus finished a year on pass 90   its label is at x = 4.0

Pass 90: 360 divided by 4. On that pass Venus is back where it started, at x = 4, and its label is at x = 4.0 as well, because the loop moved the label to the planet on every pass.

Mercury finishes on pass 60, with its label at x = 3.0, back at its start too.

What you will see, and what to do

In the roomRedirect
Forgets return p and gets AttributeError: 'NoneType' object has no attribute 'pos'.The function made the planet and gave nothing back. Ask what the line earth = make_planet(...) stored. Chunk 1's reveal has the error.
Reads p.turned before the function sets it.An attribute exists after the first assignment. Chunk 2's last line is this error on purpose; point at it.

Running this in VS Code

Once, before the first run

Open the terminal in VS Code and install the library: pip install vpython. Check it worked with python -c "import vpython". It should print nothing at all and give you the prompt back. A traceback here is an install problem, not a problem with your program.

Every run after that

Save your file as YourName_vpython05.py: your first name, an underscore, then vpython05. Run it from the terminal. The 3D scene opens in a new browser tab, sometimes behind VS Code, so look for it before deciding that nothing happened. Click inside the scene before pressing any key. To end the program, close the tab or press Ctrl+C in the terminal. The program is written to run until you do. Run the file again and you get a fresh tab.

VPython draws solid shapes that you can turn and zoom. Everything you print still goes to the terminal, and everything you draw goes to the browser tab. Words in the terminal, pictures in the tab.
