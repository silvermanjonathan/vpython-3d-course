Motion: velocity, gravity, and bouncing

A ball that moves because it has a velocity, falls because gravity changes that velocity, and bounces because one gate flips a sign

Length 90 minutes Ages 10 to 11 New 8 items

What is new today

velocity as a vector, dt, gravity changes velocity, the floor gate, flipping a sign to bounce, losing speed on each bounce, keys that push instead of move, round(x, 2).

Deliberately re-used: Session 1: the loop with rate(30), keysdown, and pos.y on its own. Session 2: vector arithmetic.

The whole session is two lines, vel = vel + gravity * dt and ball.pos = ball.pos + vel * dt, and a gate. Keep saying which line changes the velocity and which line changes the position. Students who mix them up write gravity into pos and get a ball that falls at one speed.

Opener · 10 minutes

Retrieval: the loop, the middle, and vectors

Paper first.

Question: What does rate(30) do, and what goes wrong without it?

It pauses the loop so that it runs 30 passes a second and no more. Without it the loop runs as fast as the computer can and the tab has no time to draw.

Question: The loop adds 0.1 to ball.pos.x on every pass. How far does the ball move in one second, and what is the one number to change to make it move twice as fast?

3 units: 30 passes, 0.1 each. Change the 0.1 to 0.2. Today that number gets a name, velocity, and its own vector.

Question: What is vec(2, 0, 0) + vec(0, 3, 0)? And why does a cone's pos plus its axis give the point of the cone?

<2, 3, 0>: each number adds to its partner. The cone's pos is its flat end and its axis is the vector from there to the point, so adding them gives where the point is.

Chunk 1 of 6

Velocity is a vector, and dt is a slice of a second

Velocity is how far something moves in one second, and in which direction. vel = vec(2, 0, 0) means 2 units to the right every second.

The loop runs 30 passes a second, so each pass is one thirtieth of a second. That slice is called dt. On each pass the ball moves vel * dt: the velocity, scaled down to one pass. After 30 passes the ball has moved exactly vel.

from vpython import *

ball = sphere(pos=vec(-5, 0, 0), radius=0.5, color=color.yellow)
vel = vec(2, 0, 0)
dt = 1 / 30
passes = 0

while True:
    rate(30)
    passes = passes + 1
    ball.pos = ball.pos + vel * dt
    if passes == 30:
        print("after 1 second the ball is at", ball.pos)
    if passes == 60:
        print("after 2 seconds the ball is at", ball.pos)

Predict: The ball starts at x = -5 and its velocity is 2 to the right. Where is it after one second, and after two?

What it actually prints (run without a browser, quit after 60 passes of the loop)

after 1 second the ball is at <-3, 0, 0>
after 2 seconds the ball is at <-1, 0, 0>

After one second it is at <-3, 0, 0>, and after two at <-1, 0, 0>. Two units per second, so two seconds moves it four.

Session 1 wrote ball.pos.x + 0.1. This does the same thing with the speed written as a whole number per second, so you can read the speed straight off the program.

Chunk 2 of 6

Gravity changes the velocity, and the velocity changes the position

Gravity is not a push on the position. It is a change to the velocity: on every pass, the downward speed grows by a little. Then the velocity, which is now bigger, moves the ball. Two lines, in that order.

gravity = vec(0, -9.8, 0) is the real value: a falling thing gains 9.8 units of speed every second. After 30 passes the ball falls at 9.8 per second.

round(x, 2) keeps two decimal places, so the printed numbers are readable.

from vpython import *

ball = sphere(pos=vec(0, 5, 0), radius=0.5, color=color.yellow)
vel = vec(0, 0, 0)
gravity = vec(0, -9.8, 0)
dt = 1 / 30
passes = 0

while True:
    rate(30)
    passes = passes + 1

    vel = vel + gravity * dt
    ball.pos = ball.pos + vel * dt

    if passes in [10, 20, 30]:
        print("pass", passes, "  falling at", round(-vel.y, 2), "per second   height", round(ball.pos.y, 2))

Predict: Gravity adds the same amount to the speed on every pass. How fast is the ball falling after 30 passes? And does the height drop by more between passes 20 and 30 than between passes 10 and 20?

What it actually prints (run without a browser, quit after 30 passes of the loop)

pass 10   falling at 3.27 per second   height 4.4
pass 20   falling at 6.53 per second   height 2.71
pass 30   falling at 9.8 per second   height -0.06

After 30 passes it falls at 9.8 per second, the gravity number, because one second of passes has gone by. It falls at 3.27 after 10 passes and 6.53 after 20, so the speed grows by the same 3.27 each ten passes.

The height drops by 1.69 between passes 10 and 20, and by 2.77 between 20 and 30. More, because the ball is going faster by then. The speed changes evenly; the height does not.

Chunk 3 of 6

The floor gate flips the sign

A bounce is one gate. When the ball is below the floor, put it back on the floor and turn its downward velocity into an upward one. vel.y = -vel.y does that: a speed of -9.47 becomes +9.47, the same size in the opposite direction.

The gate compares ball.pos.y with ball.radius, not with 0, because pos is the middle of the ball and the bottom of the ball touches the floor when the middle is one radius up.

from vpython import *

ground = box(pos=vec(0, -0.1, 0), size=vec(10, 0.2, 10), color=color.green)
ball = sphere(pos=vec(0, 5, 0), radius=0.5, color=color.yellow)
vel = vec(0, 0, 0)
gravity = vec(0, -9.8, 0)
dt = 1 / 30
passes = 0

while True:
    rate(30)
    passes = passes + 1

    vel = vel + gravity * dt
    ball.pos = ball.pos + vel * dt

    if ball.pos.y < ball.radius:
        ball.pos.y = ball.radius
        vel.y = -vel.y
        print("bounce on pass", passes, "  going up at", round(vel.y, 2), "per second")

Predict: The ball reaches the floor at about 9.5 per second. What is vel.y right after the first bounce? And on the second bounce, is the ball going faster, slower, or the same?

What it actually prints (run without a browser, quit after 100 passes of the loop)

bounce on pass 29   going up at 9.47 per second
bounce on pass 86   going up at 9.15 per second

Right after the first bounce vel.y is 9.47: the same number with the sign flipped, so the ball goes up as fast as it came down. The second bounce, on pass 86, is at 9.15, a little slower. No line in the program takes speed away on purpose. The small loss comes from the line ball.pos.y = ball.radius: the ball had gone a little under the floor, that bit of the move is thrown away when the ball is put back on the floor, and the speed that bit would have cost is lost with it.

That line still has to be there. Without it the ball can still be under the floor on the next pass, the gate opens again, the sign flips back, and the ball is stuck in the floor.

Chunk 4 of 6

Walls are the same gate, on x

A wall on the right is at x = 5. The ball's edge reaches it when its middle is at 5 - ball.radius. Flip vel.x there, and flip it again at the left wall. The pattern is the floor gate with x in place of y.

from vpython import *

ground = box(pos=vec(0, -0.1, 0), size=vec(10, 0.2, 10), color=color.green)
wall_left = box(pos=vec(-5, 1, 0), size=vec(0.2, 2, 10), color=color.gray(0.7))
wall_right = box(pos=vec(5, 1, 0), size=vec(0.2, 2, 10), color=color.gray(0.7))
ball = sphere(pos=vec(0, 0.5, 0), radius=0.5, color=color.yellow)
vel = vec(6, 0, 0)
dt = 1 / 30
passes = 0

while True:
    rate(30)
    passes = passes + 1
    ball.pos = ball.pos + vel * dt

    if ball.pos.x > 5 - ball.radius:
        vel.x = -vel.x
        print("hit the right wall on pass", passes, "  vel is now", vel)
    if ball.pos.x < -5 + ball.radius:
        vel.x = -vel.x
        print("hit the left wall on pass", passes, "  vel is now", vel)

Predict: The ball starts in the middle, moving right at 6 per second. The wall is 5 away, so the ball's edge touches it 4.5 from the start. Which wall does it hit first, and on about which pass?

What it actually prints (run without a browser, quit after 100 passes of the loop)

hit the right wall on pass 23   vel is now <-6, 0, 0>
hit the left wall on pass 69   vel is now <6, 0, 0>

The right wall, on pass 23. At 6 per second, 4.5 units take three quarters of a second, which is 22.5 passes, so pass 23 is the first pass where the ball is past the line. The velocity becomes <-6, 0, 0>.

The left wall comes 46 passes later, on pass 69, because the ball has to cross the whole room, 9 units, at 6 per second.

Chunk 5 of 6

Losing a little speed on every bounce

A real ball does not bounce back to the same height. Multiply the flipped velocity by a number less than 1 and each bounce is a bit lower than the one before. vel.y = -vel.y * 0.7 keeps 7 tenths of the speed.

from vpython import *

ground = box(pos=vec(0, -0.1, 0), size=vec(10, 0.2, 10), color=color.green)
ball = sphere(pos=vec(0, 5, 0), radius=0.5, color=color.yellow)
vel = vec(0, 0, 0)
gravity = vec(0, -9.8, 0)
dt = 1 / 30
passes = 0

while True:
    rate(30)
    passes = passes + 1

    vel = vel + gravity * dt
    ball.pos = ball.pos + vel * dt

    if ball.pos.y < ball.radius:
        ball.pos.y = ball.radius
        vel.y = -vel.y * 0.7
        print("bounce on pass", passes, "  going up at", round(vel.y, 2))

Predict: The first bounce sends the ball up at about 6.6 per second instead of 9.5. Will the gap between bounces get longer or shorter each time? Will the ball ever stop bouncing?

What it actually prints (run without a browser, quit after 130 passes of the loop)

bounce on pass 29   going up at 6.63
bounce on pass 69   going up at 4.5
bounce on pass 96   going up at 3.02
bounce on pass 114   going up at 2.0
bounce on pass 126   going up at 1.34

Shorter. A slower ball does not go as high, so it comes back sooner: the bounces are 40 passes apart, then 27, then 18, then 12. The speeds shrink each time: 6.63, 4.5, 3.02, 2.0, 1.34.

The bounces get smaller and closer together until, after about five seconds, they are too small to see and the ball looks like it is resting on the floor. The program is still bouncing it a tiny amount on every pass. Seven tenths of a small number is a smaller number, not zero.

Chunk 6 of 6

Keys that push

In session 1 the arrow keys changed the position. Here they change the velocity. Holding right adds push to vel.x on every pass, so the longer you hold, the faster the ball rolls. Letting go does not stop it, because nothing takes the velocity away.

from vpython import *

scene.caption = "Click the scene, then tap the right arrow."
ground = box(pos=vec(0, -0.1, 0), size=vec(10, 0.2, 10), color=color.green)
ball = sphere(pos=vec(0, 0.5, 0), radius=0.5, color=color.yellow)
vel = vec(0, 0, 0)
push = 0.3
dt = 1 / 30
passes = 0

while True:
    rate(30)
    passes = passes + 1
    keys = keysdown()

    if "right" in keys:
        vel.x = vel.x + push
    if "left" in keys:
        vel.x = vel.x - push

    ball.pos = ball.pos + vel * dt

    if passes in [3, 5, 8]:
        print("pass", passes, "  vel.x =", round(vel.x, 2), "  x =", round(ball.pos.x, 2))

Predict: The right arrow is held on passes 2, 3 and 4 and then let go. What is vel.x on pass 5, and on pass 8? Does the ball stop when the key is let go?

What it actually prints (run without a browser, quit after 8 passes of the loop)

pass 3   vel.x = 0.6   x = 0.03
pass 5   vel.x = 0.9   x = 0.09
pass 8   vel.x = 0.9   x = 0.18

Fed in by the build script: the right arrow key held on passes 2 to 4.

On pass 5 vel.x is 0.9: three passes of 0.3. On pass 8 it is still 0.9, because no gate opened after pass 4 and nothing subtracts from the velocity. The ball does not stop; x keeps growing, 0.09 at pass 5 and 0.18 at pass 8.

To make it slow down on its own, multiply vel.x by 0.98 on every pass. That is friction, and it is the stretch exit.

Hinge question · from today's chunks

Before you build

Question: Program A adds vec(0.1, 0, 0) to the ball's pos on every pass. Program B adds vel * dt with vel = vec(3, 0, 0) and dt = 1 / 30. Both run at rate(30). Which ball is faster? Now both programs change to rate(60), and B changes dt to 1 / 60. Which ball changes speed?

At rate(30) they are the same speed: A moves 0.1 thirty times a second, which is 3 per second, and B moves 3 per second by definition.

At rate(60), A doubles to 6 per second, because it still moves 0.1 on each of 60 passes. B stays at 3 per second, because each pass now moves half as much. Writing motion as vel * dt is what keeps the speed you wrote, whatever the rate.

Build · 20 minutes

Build: the bouncy room

A ball in a room 10 by 10 with four walls 2 tall. Gravity pulls it down and the floor bounces it with 8 tenths of its speed. The arrow keys push it along x and z. Pressing r puts the ball back at the top with no velocity. The camera is tilted so you can see the floor, and the ball cannot leave the room.

  1. Start from chunk 5: the ground, gravity, and the floor gate with 0.8 in place of 0.7.
  2. Add the two walls and the two x gates from chunk 4. Then add two walls at z = 5 and z = -5 and the two z gates from the card below.
  3. Add the key gates from chunk 6 for left and right on vel.x, and for up and down on vel.z. Remember that up is negative z.
  4. Add a gate inside the loop: if "r" is in the held keys, put the ball at vec(0, 5, 0) and set vel to vec(0, 0, 0).
  5. Put scene.forward = vec(0, -0.5, -1) above the loop so the camera looks down into the room, and write a caption that names the keys.

The two gates for the z walls

The far wall is at z = -5 and the near wall at z = 5. They are the x gates with z in place of x and the signs the other way round for the far wall.

from vpython import *

ground = box(pos=vec(0, -0.1, 0), size=vec(10, 0.2, 10), color=color.green)
wall_far = box(pos=vec(0, 1, -5), size=vec(10, 2, 0.2), color=color.gray(0.7))
wall_near = box(pos=vec(0, 1, 5), size=vec(10, 2, 0.2), color=color.gray(0.7), opacity=0.3)
ball = sphere(pos=vec(0, 0.5, 0), radius=0.5, color=color.yellow)
vel = vec(0, 0, -6)
dt = 1 / 30
passes = 0

while True:
    rate(30)
    passes = passes + 1
    ball.pos = ball.pos + vel * dt

    if ball.pos.z < -5 + ball.radius:
        vel.z = -vel.z
        print("hit the far wall on pass", passes, "  vel is now", vel)
    if ball.pos.z > 5 - ball.radius:
        vel.z = -vel.z
        print("hit the near wall on pass", passes, "  vel is now", vel)

Predict: The ball starts moving away from you at 6 per second. Which wall does it hit first, and what is vel after that hit?

What it actually prints (run without a browser, quit after 100 passes of the loop)

hit the far wall on pass 23   vel is now <0, 0, 6>
hit the near wall on pass 69   vel is now <0, 0, -6>

The far wall, on pass 23, because away from you is negative z and the far wall is at z = -5. After the hit vel is <0, 0, 6>, so the ball comes back toward you. The near wall is see-through, opacity 0.3, so the ball stays visible when it is close to the camera.

Running this in VS Code

Once, before the first run

Open the terminal in VS Code and install the library: pip install vpython. Check it worked with python -c "import vpython". It should print nothing at all and give you the prompt back. A traceback here is an install problem, not a problem with your program.

Every run after that

Save your file as YourName_vpython03.py: your first name, an underscore, then vpython03. Run it from the terminal. The 3D scene opens in a new browser tab, sometimes behind VS Code, so look for it before deciding that nothing happened. Click inside the scene before pressing any key. To end the program, close the tab or press Ctrl+C in the terminal. The program is written to run until you do. Run the file again and you get a fresh tab.

VPython draws solid shapes that you can turn and zoom. Everything you print still goes to the terminal, and everything you draw goes to the browser tab. Words in the terminal, pictures in the tab.
