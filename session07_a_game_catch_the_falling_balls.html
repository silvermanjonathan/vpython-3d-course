Python in 3D · VPython · Session 7 of 11

A game: catch the falling balls

A paddle on keys, a ball that falls, one gate that decides a catch, a score on screen, lives, game over, and a key that starts again

Length 90 minutes Ages 10 to 11 New 9 items

What is new today

abs for a distance, randint, a catch gate with and, str to put a number in text, wtext for a score, lives, a state name, restart from inside the loop, harder each catch.

Deliberately re-used: Session 3: velocity on the ball, keysdown in the loop. Session 6: attributes on an object.

Every piece of state in this game is a plain variable inside the loop, because there are no bound functions: the restart is a key read with keysdown. Say that at the start. Students who try to add a Reset button will hit the shared-state problem and should use the r key instead, or put the numbers on the paddle as attributes.

Opener · 10 minutes

Retrieval: attributes, the floor gate, and two kinds of key

Paper first.

Question: ball.vel = vec(0, -4, 0) is written once above the loop. What kind of thing is vel here, and who gave it to the ball?

An attribute that the program gave the ball by assigning to it. VPython did not give the ball a vel. From then on the ball carries its own velocity, and a loop over several balls can read each one's.

Question: Why does the floor gate compare ball.pos.y with the ball's radius and not with 0?

pos is the middle of the ball. The bottom of the ball is one radius below, so the ball touches the floor when its middle is one radius up.

Question: One box moves one step per tap. Another glides while the key is held. Which used a bound keydown function and which used keysdown() in the loop?

One step per tap is the bound function: VPython calls it once per press. Gliding is keysdown(): the gate runs on every pass and the key is in the list for as long as it is held.

Chunk 1 of 6

A paddle on the keys and a ball that falls

The paddle is a flat box that slides along x while an arrow key is held. The ball falls at a steady speed: its velocity is vec(0, -4, 0), 4 per second downward, and there is no gravity line, so the speed never changes. The ball's velocity is an attribute on the ball, ball.vel, the way session 6 put a speed on a planet.

from vpython import *

scene.caption = "Click the scene, then hold left or right."
ground = box(pos=vec(0, -0.1, 0), size=vec(12, 0.2, 6), color=color.green)
paddle = box(pos=vec(0, 0.25, 0), size=vec(3, 0.5, 1), color=color.blue)
ball = sphere(pos=vec(0, 8.5, 0), radius=0.4, color=color.yellow)
ball.vel = vec(0, -4, 0)
dt = 1 / 30
passes = 0

while True:
    rate(30)
    passes = passes + 1
    keys = keysdown()

    if "right" in keys:
        paddle.pos.x = paddle.pos.x + 0.3
    if "left" in keys:
        paddle.pos.x = paddle.pos.x - 0.3

    ball.pos = ball.pos + ball.vel * dt

    if passes in [30, 60]:
        print("pass", passes, "  ball height", round(ball.pos.y, 2), "  paddle x", round(paddle.pos.x, 2))

Predict: The ball starts 8.5 up and falls 4 per second. On which pass does its middle reach the paddle's height, 0.5? The right arrow is held for six passes: where is the paddle after that?

What it actually prints (run without a browser, quit after 60 passes of the loop)

pass 30   ball height 4.5   paddle x 1.8
pass 60   ball height 0.5   paddle x 1.8

Fed in by the build script: the right arrow key held on passes 5 to 10.

Pass 60. In two seconds the ball falls 8, so on pass 60 its height is 0.5, and on pass 30 it was 4.5. The output box shows both.

The paddle is at x = 1.8 after six passes of 0.3 each, and it stays there once the key is let go, because the key gates change the position, not a velocity. Nothing stops the ball at the paddle yet. That is the next chunk.

Chunk 2 of 6

The catch gate: close enough, and low enough

A catch is two things true at once: the ball is down at the paddle's height, and it is near the paddle along x. and joins the two checks into one gate.

abs(ball.pos.x - paddle.pos.x) is the gap between them along x, always as a positive number. abs throws away the minus sign, so a ball 1 to the left and a ball 1 to the right both give a gap of 1. The paddle is 3 wide, so a gap under 1.5 means the ball is over the paddle.

When the ball is caught, the gate's body sends it back to the top at a random x. randint(-4, 4) picks a whole number from -4 to 4. It comes from Python's random module, so the program imports it.

from vpython import *
from random import randint

ground = box(pos=vec(0, -0.1, 0), size=vec(12, 0.2, 6), color=color.green)
paddle = box(pos=vec(0, 0.25, 0), size=vec(3, 0.5, 1), color=color.blue)
ball = sphere(pos=vec(1, 8, 0), radius=0.4, color=color.yellow)
ball.vel = vec(0, -4, 0)
dt = 1 / 30
score = 0
passes = 0

while True:
    rate(30)
    passes = passes + 1
    ball.pos = ball.pos + ball.vel * dt

    gap = abs(ball.pos.x - paddle.pos.x)
    if ball.pos.y < 0.9 and gap < 1.5:
        score = score + 1
        print("caught on pass", passes, "  the gap was", round(gap, 2), "  score", score)
        ball.pos = vec(randint(-4, 4), 8, 0)
        print("a new ball is at the top, height", ball.pos.y)

Predict: The ball starts at x = 1 and the paddle is at x = 0. Is the gap small enough for a catch? On about which pass does the catch happen, and where does the new ball start?

What it actually prints (run without a browser, quit after 60 passes of the loop)

caught on pass 54   the gap was 1.0   score 1
a new ball is at the top, height 8.0

Yes: the gap is 1.0, under 1.5. The catch happens on pass 54, the first pass where the ball's height is under 0.9. 7.1 units at 4 per second is 1.775 seconds, which is a little more than 53 passes.

The new ball starts at height 8 and at an x chosen by randint. The output box shows the x of one run; on your run it will probably be a different whole number from -4 to 4, because that is what random means.

Chunk 3 of 6

Missing the ball costs a life

If the whole ball is under the ground, lower than -0.5, it was missed. That is a second gate, after the catch gate: lives go down by one and the ball goes back to the top. The paddle in this program is far away at x = -8 so that no catch can happen and every ball is missed.

from vpython import *
from random import randint

ground = box(pos=vec(0, -0.1, 0), size=vec(12, 0.2, 6), color=color.green)
paddle = box(pos=vec(-8, 0.25, 0), size=vec(3, 0.5, 1), color=color.blue)
ball = sphere(pos=vec(1, 8, 0), radius=0.4, color=color.yellow)
ball.vel = vec(0, -4, 0)
dt = 1 / 30
lives = 3
passes = 0

while True:
    rate(30)
    passes = passes + 1
    ball.pos = ball.pos + ball.vel * dt

    if ball.pos.y < -0.5:
        lives = lives - 1
        print("missed on pass", passes, "  lives left", lives)
        ball.pos = vec(randint(-4, 4), 8, 0)

Predict: Every ball is missed. The first miss is on the first pass where the ball's height is below -0.5. On about which pass is that, and on which pass do the lives reach 0?

What it actually prints (run without a browser, quit after 200 passes of the loop)

missed on pass 64   lives left 2
missed on pass 128   lives left 1
missed on pass 192   lives left 0

The first miss is on pass 64: the ball falls 8.5 units, from 8 to -0.5, at 4 per second, which takes 2.125 seconds, and pass 64 is the first pass past that. Each new ball starts at 8 again, so the misses come every 64 passes: 64, 128, 192. Lives reach 0 on pass 192.

The program keeps dropping balls after that, and lives would go to -1. Chunk 5 stops the game instead.

Chunk 4 of 6

The score on the screen

wtext puts a line of text under the scene, and assigning to its text changes it. The text has to be a string. str(score) changes the number 3 into the string "3", and + joins two strings. Without str, joining a string to a number is an error.

The paddle here is wide enough to catch everything, so the score climbs on every ball.

from vpython import *
from random import randint

ground = box(pos=vec(0, -0.1, 0), size=vec(12, 0.2, 6), color=color.green)
paddle = box(pos=vec(0, 0.25, 0), size=vec(12, 0.5, 1), color=color.blue)
ball = sphere(pos=vec(1, 8, 0), radius=0.4, color=color.yellow)
ball.vel = vec(0, -4, 0)
dt = 1 / 30
score = 0
score_text = wtext(text="Score: 0")
passes = 0

while True:
    rate(30)
    passes = passes + 1
    ball.pos = ball.pos + ball.vel * dt

    gap = abs(ball.pos.x - paddle.pos.x)
    if ball.pos.y < 0.9 and gap < 6:
        score = score + 1
        score_text.text = "Score: " + str(score)
        print("pass", passes, "  the text under the scene now says:", score_text.text)
        ball.pos = vec(randint(-4, 4), 8, 0)

Predict: What does the line under the scene say after the second catch? What would go wrong if the line were "Score: " + score with no str?

What it actually prints (run without a browser, quit after 120 passes of the loop)

pass 54   the text under the scene now says: Score: 1
pass 108   the text under the scene now says: Score: 2

It says Score: 2, and the output box shows the text after each catch, on passes 54 and 108.

Without str, Python is asked to join a string to a number, and it stops with TypeError: can only concatenate str (not "int") to str. str(score) changes the type of the number to a string first, and then the join works.

Chunk 5 of 6

A state name: playing, or over

A game is not always being played. Keep a variable called state that holds "play" or "over", and gate the ball's movement on it. When lives reach 0, the state becomes over, the ball stops, and a label says so. Pressing r puts everything back and the state becomes play.

The restart is a key read with keysdown inside the loop, so every number it resets is a plain variable the loop already owns.

from vpython import *
from random import randint

scene.caption = "Click the scene. When the game is over, press r to play again."
ground = box(pos=vec(0, -0.1, 0), size=vec(12, 0.2, 6), color=color.green)
paddle = box(pos=vec(-8, 0.25, 0), size=vec(3, 0.5, 1), color=color.blue)
ball = sphere(pos=vec(1, 8, 0), radius=0.4, color=color.yellow)
ball.vel = vec(0, -4, 0)
sign = label(pos=vec(0, 4, 0), text="", height=24, box=False)
dt = 1 / 30
lives = 3
state = "play"
passes = 0

while True:
    rate(30)
    passes = passes + 1
    keys = keysdown()

    if state == "play":
        ball.pos = ball.pos + ball.vel * dt

    if state == "play" and ball.pos.y < -0.5:
        lives = lives - 1
        ball.pos = vec(randint(-4, 4), 8, 0)
        print("missed on pass", passes, "  lives left", lives)

    if state == "play" and lives == 0:
        state = "over"
        sign.text = "Game over. Press r."
        print("pass", passes, "  state is now", state)

    if state == "over" and "r" in keys:
        state = "play"
        lives = 3
        sign.text = ""
        ball.pos = vec(randint(-4, 4), 8, 0)
        print("pass", passes, "  restarted, state is", state, " lives", lives)

Predict: r is pressed on pass 100 and again on pass 200. The game is over on pass 192. Which of the two presses restarts it, and why does the other one do nothing?

What it actually prints (run without a browser, quit after 210 passes of the loop)

missed on pass 64   lives left 2
missed on pass 128   lives left 1
missed on pass 192   lives left 0
pass 192   state is now over
pass 200   restarted, state is play  lives 3

Fed in by the build script: the r key held on pass 100, the r key held on pass 200.

The press on pass 200 restarts it: the state is over by then, so the gate state == "over" and "r" in keys is True, and the output box shows the restart with lives back at 3.

The press on pass 100 does nothing, because the state is still play, and the restart gate needs both halves to be True. Pressing r in the middle of a game should not throw the game away, and that one and is what makes sure it does not.

Chunk 6 of 6

Harder with every catch

Each catch makes the next ball fall faster: subtract 1 from ball.vel.y, which is already negative, so the ball falls 1 unit per second faster. The paddle here is wide enough to catch everything, so you can watch the speed climb.

from vpython import *
from random import randint

ground = box(pos=vec(0, -0.1, 0), size=vec(12, 0.2, 6), color=color.green)
paddle = box(pos=vec(0, 0.25, 0), size=vec(12, 0.5, 1), color=color.blue)
ball = sphere(pos=vec(1, 8, 0), radius=0.4, color=color.yellow)
ball.vel = vec(0, -4, 0)
dt = 1 / 30
score = 0
passes = 0

while True:
    rate(30)
    passes = passes + 1
    ball.pos = ball.pos + ball.vel * dt

    gap = abs(ball.pos.x - paddle.pos.x)
    if ball.pos.y < 0.9 and gap < 6:
        score = score + 1
        ball.vel.y = ball.vel.y - 1
        ball.pos = vec(randint(-4, 4), 8, 0)
        print("catch", score, "on pass", passes, "  the next ball falls at", -ball.vel.y, "per second")

Predict: The first ball takes 54 passes to reach the paddle at 4 per second. The second ball falls at 5 per second. Does it take more passes or fewer? About how many?

What it actually prints (run without a browser, quit after 140 passes of the loop)

catch 1 on pass 54   the next ball falls at 5.0 per second
catch 2 on pass 97   the next ball falls at 6.0 per second
catch 3 on pass 133   the next ball falls at 7.0 per second

Fewer: 43 passes, so the second catch is on pass 97. The ball has 7.1 units to fall at 5 per second, which is 1.42 seconds. The third ball, at 6 per second, takes 36 passes and is caught on pass 133.

Every catch takes a bigger bite out of the time the player has. That one line is what makes the game get harder.

Hinge question · from today's chunks

Before you build

Question: A student's score climbs by about 30 a second after the first catch, and keeps climbing. The catch gate is if ball.pos.y < 0.9 and gap < 1.5: and its body adds 1 to the score. What is missing from the body, and why does the score climb by about 30 a second?

The body never moves the ball back to the top. The ball keeps falling through the paddle, the gate is still True on the next pass, and the next, so the score goes up once per pass, which is 30 times a second.

The fix is the line ball.pos = vec(randint(-4, 4), 8, 0) inside the body. Once the ball is at the top, the gate is False until the ball comes down again. A gate that should fire once has to change the thing it checks.

The catch gate in two directions

The paddle is 3 wide along x and 3 deep along z, so a catch needs the x gap under 1.5 and the z gap under 1.5. Three checks joined by and. The ball drops from a random x and a random z.

from vpython import *
from random import randint

scene.caption = "Click the scene. Arrow keys move the paddle along x and z."
ground = box(pos=vec(0, -0.1, 0), size=vec(12, 0.2, 12), color=color.green)
paddle = box(pos=vec(0, 0.25, 0), size=vec(3, 0.5, 3), color=color.blue)
ball = sphere(pos=vec(1, 8, -1), radius=0.4, color=color.yellow)
ball.vel = vec(0, -4, 0)
dt = 1 / 30
score = 0
passes = 0

while True:
    rate(30)
    passes = passes + 1
    keys = keysdown()

    if "right" in keys:
        paddle.pos.x = paddle.pos.x + 0.3
    if "left" in keys:
        paddle.pos.x = paddle.pos.x - 0.3
    if "up" in keys:
        paddle.pos.z = paddle.pos.z - 0.3
    if "down" in keys:
        paddle.pos.z = paddle.pos.z + 0.3

    ball.pos = ball.pos + ball.vel * dt

    gap_x = abs(ball.pos.x - paddle.pos.x)
    gap_z = abs(ball.pos.z - paddle.pos.z)
    if ball.pos.y < 0.9 and gap_x < 1.5 and gap_z < 1.5:
        score = score + 1
        print("caught on pass", passes, "  gaps were", round(gap_x, 2), "and", round(gap_z, 2), "  score", score)
        ball.pos = vec(randint(-4, 4), 8, randint(-4, 4))

Predict: The ball will land at x = 1, z = -1. The paddle starts at the middle and up is held for three passes. Where is the paddle then, and is the ball caught?

What it actually prints (run without a browser, quit after 60 passes of the loop)

caught on pass 54   gaps were 1.0 and 0.1   score 1

Fed in by the build script: the up arrow key held on passes 10 to 12.

The paddle is at z = -0.9 after three passes of 0.3 toward negative z, and still at x = 0. The x gap is 1.0 and the z gap is 0.1, both under 1.5, so the ball is caught on pass 54. The output box shows both gaps.

Had up not been pressed, the z gap would be 1.0, which is also under 1.5, so the ball would be caught anyway. A ball at z = -2 would need the move.

Running this in VS Code

Once, before the first run

Open the terminal in VS Code and install the library: pip install vpython. Check it worked with python -c "import vpython". It should print nothing at all and give you the prompt back. A traceback here is an install problem, not a problem with your program.

Every run after that

Save your file as YourName_vpython07.py: your first name, an underscore, then vpython07. Run it from the terminal. The 3D scene opens in a new browser tab, sometimes behind VS Code, so look for it before deciding that nothing happened. Click inside the scene before pressing any key. To end the program, close the tab or press Ctrl+C in the terminal. The program is written to run until you do. Run the file again and you get a fresh tab.

VPython draws solid shapes that you can turn and zoom. Everything you print still goes to the terminal, and everything you draw goes to the browser tab. Words in the terminal, pictures in the tab.
