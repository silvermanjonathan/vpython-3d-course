Opener · 10 minutes

Retrieval: gates that fire once, and attributes

Paper first.

Question: A catch gate adds 1 to the score and does nothing else. Why does the score climb 30 times a second, and what has to be in the gate's body?

The gate is True on every pass while the ball is over the paddle, so the body runs every pass. The body has to change what the gate checks, by sending the ball back to the top, so the gate closes.

Question: What does abs(3 - 5) give, and what is abs for in a game?

2. abs throws away the minus sign, so a gap is the same number whichever side the ball is on.

Question: player.score = 0 is written above the loop. Can a bound function add to it? Could it add to a plain variable called score?

Yes to the first: the attribute lives on the player, and any function that can see the player can change it. No to the second: a function cannot assign to a plain variable that lives outside it. That is why the course puts shared numbers on objects.

Chunk 1 of 6

A level is a list of strings

Each string is one row of the level, read from the far edge to the near edge. # is a wall, . is floor, and G is the goal. A string can be indexed like a list: level[2] is the third row, and level[2][2] is the third character of it. Row first, then column, and both start at 0.

from vpython import *

level = [
    "#######",
    "#.....#",
    "#.##..#",
    "#....G#",
    "#######",
]
print(len(level), "rows")
print(len(level[0]), "columns")
print("row 2 is", level[2])
print("row 2, column 2 is", level[2][2])
print("row 3, column 5 is", level[3][5])

Predict: Which pair of indexes finds the G? Say the row and the column, in that order. What is at row 2, column 2?

What it actually prints (run without a browser)

5 rows
7 columns
row 2 is #.##..#
row 2, column 2 is #
row 3, column 5 is G

The G is at row 3, column 5: level[3][5]. Count rows from the top starting at 0, then characters from the left starting at 0.

Row 2, column 2 is #, the first of the two walls in the middle of the third row. Reading it as column 2, row 2 happens to give the same character on this level, because the level is nearly square; on a level that is 5 by 7 the swap gives a different answer, and the build brief's level is 9 by 9 so that the mistake shows.

Chunk 2 of 6

Two loops draw the walls

A loop over the rows, and inside it a loop over the characters in that row. Every # becomes a box. The column number becomes x and the row number becomes z, each with 3 or 2 subtracted so the level is centred on the middle of the world.

Row 0 is the far edge, at negative z, the way the top line of a map is the far side when the map lies flat on a table.

from vpython import *

level = [
    "#######",
    "#.....#",
    "#.##..#",
    "#....G#",
    "#######",
]
walls = 0

for row in range(len(level)):
    for col in range(len(level[row])):
        if level[row][col] == "#":
            box(pos=vec(col - 3, 0.5, row - 2), color=color.gray(0.6))
            walls = walls + 1

print(walls, "wall blocks")
print("the top-left wall, row 0 col 0, is at", vec(0 - 3, 0.5, 0 - 2))
print("the bottom-right wall, row 4 col 6, is at", vec(6 - 3, 0.5, 4 - 2))

Predict: How many wall blocks are drawn? The top-left wall is row 0, column 0. Is it near you or far away, on the left or the right?

What it actually prints (run without a browser)

22 wall blocks
the top-left wall, row 0 col 0, is at <-3, 0.5, -2>
the bottom-right wall, row 4 col 6, is at <3, 0.5, 2>

22: seven on the top row, seven on the bottom, two on the second and fourth rows, and four on the middle row.

The top-left wall is at <-3, 0.5, -2>: on the left, because column 0 gives the smallest x, and far away, because row 0 gives the smallest z and negative z is away from you. The bottom-right wall is at <3, 0.5, 2>, on the right and near you.

Chunk 3 of 6

The player has a row and a column

The player's place in the level is a row and a column, kept on the player as two attributes. A function called place turns them into a pos with the same arithmetic the walls used. Change the row or column, call place, and the player appears on the new tile.

from vpython import *

player = sphere(radius=0.4, color=color.yellow)
player.row = 1
player.col = 1

def place(thing):
    thing.pos = vec(thing.col - 3, 0.5, thing.row - 2)

place(player)
print("player at row", player.row, "col", player.col, "  pos", player.pos)

player.col = 4
place(player)
print("after moving to col 4,  pos", player.pos)

Predict: After player.col = 4 and place(player), which of the three pos numbers changes, and to what?

What it actually prints (run without a browser)

player at row 1 col 1   pos <-2, 0.5, -1>
after moving to col 4,  pos <1, 0.5, -1>

Only x changes, from -2 to 1: column 4 minus 3. The row is still 1, so z is still -1, and y is always 0.5.

place works on any object that has a row and a col, which is why its parameter is called thing. The coins in chunk 6 use the same function.

Chunk 4 of 6

One step per tap, and a wall says no

Each arrow tap works out the row and column the player wants to go to, and a function called is_open says whether that tile is floor. != means is not equal to, so is_open returns True for any character except a wall. If the tile is open, the player's row and column change and place moves it. If not, nothing changes.

The ring of # around the edge of the level is what keeps the row and column inside the list. Without it a step off the edge would ask for a row that does not exist.

from vpython import *

scene.caption = "Click the scene, then tap the arrow keys."
level = [
    "#######",
    "#.....#",
    "#.##..#",
    "#....G#",
    "#######",
]
for row in range(len(level)):
    for col in range(len(level[row])):
        if level[row][col] == "#":
            box(pos=vec(col - 3, 0.5, row - 2), color=color.gray(0.6))

player = sphere(radius=0.4, color=color.yellow)
player.row = 1
player.col = 1

def place(thing):
    thing.pos = vec(thing.col - 3, 0.5, thing.row - 2)

def is_open(row, col):
    return level[row][col] != "#"

def step(evt):
    new_row = player.row
    new_col = player.col
    if evt.key == "up":
        new_row = player.row - 1
    if evt.key == "down":
        new_row = player.row + 1
    if evt.key == "left":
        new_col = player.col - 1
    if evt.key == "right":
        new_col = player.col + 1

    if is_open(new_row, new_col):
        player.row = new_row
        player.col = new_col
        place(player)
        print(evt.key, "-> row", player.row, "col", player.col)
    else:
        print(evt.key, "-> blocked by a wall")

place(player)
scene.bind("keydown", step)

while True:
    rate(30)

Predict: The player starts at row 1, column 1. The taps are right, right, down, right, down, down. Which tap is blocked, and where is the player at the end?

What it actually prints (run without a browser, quit after 10 passes of the loop)

right -> row 1 col 3
down -> blocked by a wall
right -> row 1 col 4
down -> row 2 col 4

Fed in by the build script: the right arrow key pressed on pass 1, the right arrow key pressed on pass 2, the down arrow key pressed on pass 3, the right arrow key pressed on pass 4, the down arrow key pressed on pass 5, the down arrow key pressed on pass 6.

The first down is blocked. After two rights the player is at row 1, column 3, and row 2, column 3 is a #, so is_open returns False and the player stays. The output box shows that line as blocked.

At the end the player is at row 3, column 4: the third right takes it to column 4, and the two downs take it to row 3, because rows 2 and 3 are open at column 4. The up arrow makes the row smaller, because row 0 is the far edge.

Chunk 5 of 6

A goal tile, and counting the steps

After each move, look at the character under the player. If it is G, the player has won. A counter on the player, player.steps, goes up by one for each move that happened, and a label says how many it took. A blocked tap is not a step.

from vpython import *

level = [
    "#######",
    "#.....#",
    "#.##..#",
    "#....G#",
    "#######",
]
for row in range(len(level)):
    for col in range(len(level[row])):
        if level[row][col] == "#":
            box(pos=vec(col - 3, 0.5, row - 2), color=color.gray(0.6))

player = sphere(radius=0.4, color=color.yellow)
player.row = 1
player.col = 1
player.steps = 0
sign = label(pos=vec(0, 2, 0), text="", height=20, box=False)

def place(thing):
    thing.pos = vec(thing.col - 3, 0.5, thing.row - 2)

def is_open(row, col):
    return level[row][col] != "#"

def step(evt):
    new_row = player.row
    new_col = player.col
    if evt.key == "up":
        new_row = player.row - 1
    if evt.key == "down":
        new_row = player.row + 1
    if evt.key == "left":
        new_col = player.col - 1
    if evt.key == "right":
        new_col = player.col + 1

    if is_open(new_row, new_col):
        player.row = new_row
        player.col = new_col
        player.steps = player.steps + 1
        place(player)

    if level[player.row][player.col] == "G":
        sign.text = "You reached the goal in " + str(player.steps) + " steps"
        print(sign.text)

place(player)
scene.bind("keydown", step)

while True:
    rate(30)

Chunk 6 of 6

Coins are objects in a list, each with a row and a column

A coin is a small sphere with its own row and col, placed by the same place function. The drawing loop makes one for every o in the level and appends it to a list. After each move, a loop over the coins asks whether any visible coin is on the player's tile. If one is, it is hidden and the score goes up.

from vpython import *

level = [
    "#######",
    "#.o...#",
    "#.##o.#",
    "#..o.G#",
    "#######",
]
coins = []
for row in range(len(level)):
    for col in range(len(level[row])):
        if level[row][col] == "#":
            box(pos=vec(col - 3, 0.5, row - 2), color=color.gray(0.6))
        if level[row][col] == "o":
            c = sphere(radius=0.15, color=color.yellow)
            c.row = row
            c.col = col
            coins.append(c)

player = sphere(radius=0.4, color=color.cyan)
player.row = 1
player.col = 1
player.score = 0

def place(thing):
    thing.pos = vec(thing.col - 3, 0.5, thing.row - 2)

def is_open(row, col):
    return level[row][col] != "#"

def step(evt):
    new_row = player.row
    new_col = player.col
    if evt.key == "up":
        new_row = player.row - 1
    if evt.key == "down":
        new_row = player.row + 1
    if evt.key == "left":
        new_col = player.col - 1
    if evt.key == "right":
        new_col = player.col + 1

    if is_open(new_row, new_col):
        player.row = new_row
        player.col = new_col
        place(player)

    for c in coins:
        if c.visible and c.row == player.row and c.col == player.col:
            c.visible = False
            player.score = player.score + 1
            print("coin at row", c.row, "col", c.col, "  score", player.score)

for c in coins:
    place(c)
place(player)
scene.bind("keydown", step)
print(len(coins), "coins on the level")

while True:
    rate(30)

Predict: There are three coins. The taps are right, right, right, down, down, right, left. How many coins are collected, and why does the last left, which moves the player back onto a coin's tile, not score again?

What it actually prints (run without a browser, quit after 10 passes of the loop)

3 coins on the level
coin at row 1 col 2   score 1
coin at row 2 col 4   score 2

Fed in by the build script: the right arrow key pressed on pass 1, the right arrow key pressed on pass 2, the right arrow key pressed on pass 3, the down arrow key pressed on pass 4, the down arrow key pressed on pass 5, the right arrow key pressed on pass 6, the left arrow key pressed on pass 7.

Two coins: the one at row 1, column 2 on the first right, and the one at row 2, column 4 on the first down. The coin at row 3, column 3 is never stepped on.

The last left moves the player back to row 3, column 4, which never had a coin, so nothing scores. Even on a tile that did have one, the gate checks c.visible first, and a collected coin is hidden, so it cannot be collected twice. Hiding the coin is the change that closes the gate, the same idea as the catch gate sending the ball back to the top.

Hinge question · from today's chunks

Before you build

Question: A level is 5 strings long and each string has 7 characters. Give len(level) and len(level[0]). Give the row and column of the bottom-right corner. Then say which of row and column becomes x in the drawing, and which becomes z.

len(level) is 5, the number of rows. len(level[0]) is 7, the number of characters in a row.

The bottom-right corner is row 4, column 6: one less than each length, because both start at 0.

Column becomes x, because columns run across. Row becomes z, because rows run from far to near. Swapping them draws the level turned on its side.

Build · 20 minutes

Build: the coin maze

A maze 9 by 9 drawn from a list of strings, with walls, a start, coins, and a goal. The player moves one tile per arrow tap and cannot walk through walls. A line of text under the scene shows the score and the step count. Reaching the goal shows a label. Pressing r puts the player back at the start, the coins back, and the counts back to 0. The camera looks down at the maze from above.

  1. Start from the card below: the 9 by 9 level, the drawing loop with the middle column and middle row as two named numbers, and place written from them.
  2. Add the player at row 1, column 1 with row, col, steps and score attributes, and the step function from chunk 6 with the step counter from chunk 5.
  3. Add a wtext under the scene and set its text after every move: "Coins: " + str(player.score) + " Steps: " + str(player.steps).
  4. Add the goal label from chunk 5.
  5. Add a restart: a key r inside the step function that puts the player's row and col back to 1, both counters back to 0, every coin's visible back to True, and the label's text back to empty.
  6. Put scene.forward = vec(0, -1, -0.3) and scene.range = 6 above the loop so the whole maze is in view from above.

A bigger level, with the middle written once

Nine columns and nine rows, so the middle is column 4 and row 4. Those two numbers are written once at the top, and both the drawing loop and place use them. Change the level's size and only those two numbers change.

from vpython import *

level = [
    "#########",
    "#..o#...#",
    "#.#.#.#.#",
    "#.#...#o#",
    "#.#####.#",
    "#o..#...#",
    "#.#.#.#.#",
    "#...#..G#",
    "#########",
]
mid_col = 4
mid_row = 4
coins = []
walls = 0

for row in range(len(level)):
    for col in range(len(level[row])):
        if level[row][col] == "#":
            box(pos=vec(col - mid_col, 0.5, row - mid_row), color=color.gray(0.6))
            walls = walls + 1
        if level[row][col] == "o":
            c = sphere(radius=0.15, color=color.yellow)
            c.row = row
            c.col = col
            coins.append(c)

def place(thing):
    thing.pos = vec(thing.col - mid_col, 0.5, thing.row - mid_row)

for c in coins:
    place(c)

print(walls, "walls and", len(coins), "coins")
print("the middle tile, row 4 col 4, is at", vec(4 - mid_col, 0.5, 4 - mid_row))
print("the goal, row 7 col 7, is at", vec(7 - mid_col, 0.5, 7 - mid_row))

Running this in VS Code

Once, before the first run

Open the terminal in VS Code and install the library: pip install vpython. Check it worked with python -c "import vpython". It should print nothing at all and give you the prompt back. A traceback here is an install problem, not a problem with your program.

Every run after that

Save your file as YourName_vpython08.py: your first name, an underscore, then vpython08. Run it from the terminal. The 3D scene opens in a new browser tab, sometimes behind VS Code, so look for it before deciding that nothing happened. Click inside the scene before pressing any key. To end the program, close the tab or press Ctrl+C in the terminal. The program is written to run until you do. Run the file again and you get a fresh tab.

VPython draws solid shapes that you can turn and zoom. Everything you print still goes to the terminal, and everything you draw goes to the browser tab. Words in the terminal, pictures in the tab.
