Opener · 10 minutes

Retrieval: velocity, the floor gate, and axis

Paper first.

vel = vel + gravity * dt
ball.pos = ball.pos + vel * dt

Question: Which line changes the velocity and which line changes the position? Say what goes wrong if gravity is added to the position instead.

The first line changes the velocity: gravity adds a little downward speed every pass. The second changes the position by the velocity. Added to the position instead, gravity moves the ball down by the same amount every pass, so it falls at one steady speed and never speeds up.

Question: The bounce line is vel.y = -vel.y. What happens to a ball that was falling at 9 per second?

It goes up at 9 per second. The minus flips the sign and keeps the size, so the direction changes and the speed does not.

Question: A cylinder has pos=vec(0, 0, 0) and axis=vec(0, 3, 0). Where is its top, and how tall is it?

The top is at <0, 3, 0>, pos plus axis. It is 3 tall, which is mag(axis).

Chunk 1 of 6

rotate turns a thing around a line through its pos

blade.rotate(angle=radians(60), axis=vec(0, 0, 1)) turns the blade by 60 degrees around a line that points along z and passes through the blade's pos. radians(60) is how you write 60 degrees to VPython. Always write the angle that way; a bare number means something else, and the hinge question is about what.

A box's axis is a vector along its length. Turning the box turns its axis with it. The length does not change, only the direction.

from vpython import *

blade = box(pos=vec(0, 0, 0), size=vec(4, 0.4, 0.2), color=color.red)
print("blade axis before:", blade.axis, "  length", mag(blade.axis))

blade.rotate(angle=radians(60), axis=vec(0, 0, 1))
print("blade axis after 60 degrees:", blade.axis, "  length", mag(blade.axis))

Predict: The blade is 4 long, so its axis is <4, 0, 0>. After turning 60 degrees, is the axis longer, shorter, or the same length? Does its x number get bigger or smaller?

What it actually prints (run without a browser)

blade axis before: <4, 0, 0>   length 4.0
blade axis after 60 degrees: <2, 3.4641, 0>   length 4.0

The same length: 4.0 before and 4.0 after. Turning does not stretch anything.

The x number gets smaller, from 4 to 2, and the y number grows from 0 to 3.4641. The blade now points up and to the right instead of straight right, so less of its length is along x and some of it is along y. In the tab the blade is tilted like a clock hand at two o'clock.

Chunk 2 of 6

A little turn on every pass is a spin

Turn the blade by 3 degrees on every pass and it spins. A counter called turned adds up the degrees, and a gate on 360 says when one full turn is done. That is how you check that the turn is the size you meant.

Thirty passes a second at 3 degrees each is 90 degrees a second, so a full turn takes 4 seconds.

from vpython import *

hub = cylinder(pos=vec(0, 0, -0.5), axis=vec(0, 0, 1), radius=0.3, color=color.gray(0.5))
blade = box(pos=vec(0, 0, 0), size=vec(4, 0.4, 0.2), color=color.red)
step = 3
turned = 0
passes = 0

while True:
    rate(30)
    passes = passes + 1

    blade.rotate(angle=radians(step), axis=vec(0, 0, 1))
    turned = turned + step

    if turned == 360:
        print("one full turn after", passes, "passes, which is", passes / 30, "seconds")
        turned = 0

Predict: 3 degrees per pass, 30 passes a second. On which pass is the first full turn finished, and how many seconds is that? What single number change makes the blade spin twice as fast?

What it actually prints (run without a browser, quit after 240 passes of the loop)

one full turn after 120 passes, which is 4.0 seconds
one full turn after 240 passes, which is 8.0 seconds

The first full turn finishes on pass 120, which is 4.0 seconds: 360 divided by 3 is 120 passes. The second finishes on pass 240.

Change step to 6. Then each pass turns twice as far, the counter reaches 360 on pass 60, and a full turn takes 2 seconds. Nothing else in the program needs to change, because every line uses step.

Chunk 3 of 6

rotate with an origin goes around another point

Add origin=planet.pos and the moon turns around the planet instead of around its own middle. Its pos changes on every pass, and its distance from the planet does not.

The prints use round(x, 2) from session 3, because a turned position has many decimal places and two are enough to read.

from vpython import *

planet = sphere(pos=vec(0, 0, 0), radius=1, color=color.blue)
moon = sphere(pos=vec(3, 0, 0), radius=0.3, color=color.white)
passes = 0

while True:
    rate(30)
    passes = passes + 1
    moon.rotate(angle=radians(10), axis=vec(0, 1, 0), origin=planet.pos)

    if passes in [3, 6, 9]:
        print("pass", passes, "  moon x =", round(moon.pos.x, 2), "  z =", round(moon.pos.z, 2),
              "  distance from planet", round(mag(moon.pos - planet.pos), 2))

Predict: The moon starts 3 to the right of the planet and turns 10 degrees per pass around the planet. After 9 passes it has turned 90 degrees. Where is it then, and how far is it from the planet?

What it actually prints (run without a browser, quit after 9 passes of the loop)

pass 3   moon x = 2.6   z = -1.5   distance from planet 3.0
pass 6   moon x = 1.5   z = -2.6   distance from planet 3.0
pass 9   moon x = 0.0   z = -3.0   distance from planet 3.0

After 9 passes the moon is at x = 0.0 and z = -3.0: straight behind the planet, away from you, still 3.0 away. The distance is 3.0 on every line, because turning around a point keeps you the same distance from it.

Without origin=, the moon would turn around its own middle, which for a sphere changes nothing you can see.

Chunk 4 of 6

Turn the car with a key, then drive the way it faces

Left and right are single taps, so they go in a bound function: each tap turns the car 30 degrees around the up direction. Up is held, so it goes in the loop.

Driving forward means moving along the car's own axis, whichever way that points now. norm(car.axis) is the axis shrunk to length 1, the direction only. Multiply it by 0.2 and you have a move of 0.2 in the direction the car is facing.

from vpython import *

scene.caption = "Click the scene. Left and right turn the car. Up drives it."
ground = box(pos=vec(0, -0.1, 0), size=vec(20, 0.2, 20), color=color.green)
car = box(pos=vec(0, 0.5, 0), size=vec(2, 1, 1), color=color.red)
start = vec(0, 0.5, 0)

def steer(evt):
    if evt.key == "left":
        car.rotate(angle=radians(30), axis=vec(0, 1, 0))
    if evt.key == "right":
        car.rotate(angle=radians(-30), axis=vec(0, 1, 0))
    print("car now points along", car.axis)

scene.bind("keydown", steer)

while True:
    rate(30)
    keys = keysdown()
    if "up" in keys:
        car.pos = car.pos + norm(car.axis) * 0.2
        print("car at", car.pos, "  distance from start", round(mag(car.pos - start), 2))

Predict: Left is tapped once, then up is held for two passes. Is the car 0.4 from where it started? Did it move along x only, or along x and z?

What it actually prints (run without a browser, quit after 6 passes of the loop)

car now points along <1.73205, 0, -1>
car at <0.173205, 0.5, -0.1>   distance from start 0.2
car at <0.34641, 0.5, -0.2>   distance from start 0.4

Fed in by the build script: the left arrow key pressed on pass 2, the up arrow key held on passes 4 to 5.

It is 0.4 from the start: 0.2 per pass for two passes, whatever direction it faces. The line that moves it uses norm, so the move is always exactly 0.2 long.

It moved along x and z both. After the left tap the axis is <1.73205, 0, -1>: mostly along x, partly away from you. So each pass moves the car 0.17 along x and 0.1 along negative z, and the output box shows x growing and z going negative together.

Chunk 5 of 6

The camera: where it looks and how much it shows

scene.center is the point the camera looks at, and scene.range is how many units it shows from the middle to the edge. By default the camera zooms out on its own to keep everything in view; scene.autoscale = False stops that, so a car can drive out of sight.

scene.forward is the direction the camera looks. vec(0, -0.5, -1) looks away from you and a bit down, so the ground is seen from above.

Assigning the car's pos to scene.center moves the camera to look at the car. Doing that on every pass is what scene.camera.follow(car) does in one line.

from vpython import *

ground = box(pos=vec(0, -0.1, 0), size=vec(40, 0.2, 40), color=color.green)
car = box(pos=vec(0, 0.5, 0), size=vec(2, 1, 1), color=color.red)
scene.autoscale = False
scene.range = 8
scene.forward = vec(0, -0.5, -1)
print("the camera looks at", scene.center, " and shows", scene.range, "units each way")
passes = 0

while True:
    rate(30)
    passes = passes + 1
    car.pos = car.pos + vec(0.2, 0, 0)

    if passes == 60:
        print("car is at", car.pos, "  camera still looks at", scene.center)
        scene.center = car.pos
        print("after scene.center = car.pos, the camera looks at", scene.center)

Predict: The view shows 8 units each way and the car drives right at 0.2 per pass. On about which pass does the car leave the view? And where is the camera looking on pass 60, before the center line runs?

What it actually prints (run without a browser, quit after 60 passes of the loop)

the camera looks at <0, 0, 0>  and shows 8 units each way
car is at <12, 0.5, 0>   camera still looks at <0, 0, 0>
after scene.center = car.pos, the camera looks at <12, 0.5, 0>

About pass 40: 8 units at 0.2 per pass is 40 passes, and after that the car is past the right edge. The view does not move to follow it, because autoscale is off.

On pass 60 the camera still looks at <0, 0, 0> while the car is at x = 12. After scene.center = car.pos the camera looks at <12, 0.5, 0> and the car is back in the middle of the view. Put that line inside the loop, or write scene.camera.follow(car) once above it, and the view stays on the car.

Chunk 6 of 6

Turning a whole model

A model is a list of parts, from session 2. To turn the whole model, rotate every part around the same point: the body's pos. Parts that are not at that point move around it, the way the moon did, and parts at that point turn in place.

from vpython import *

body = box(pos=vec(0, 0.5, 0), size=vec(2, 1, 1), color=color.red)
parts = [body]
parts.append(sphere(pos=vec(1, 0.5, 0), radius=0.3, color=color.yellow))
parts.append(sphere(pos=vec(-1, 0.5, 0), radius=0.3, color=color.yellow))

for part in parts:
    part.rotate(angle=radians(60), axis=vec(0, 1, 0), origin=body.pos)

for part in parts:
    print("part at x =", round(part.pos.x, 2), " z =", round(part.pos.z, 2))

Predict: The two lights sit 1 to the right and 1 to the left of the body. After the whole model turns 60 degrees, is the body's pos different? Are the lights still 1 away from the body?

What it actually prints (run without a browser)

part at x = 0.0  z = 0.0
part at x = 0.5  z = -0.87
part at x = -0.5  z = 0.87

The body's pos is the same, x = 0.0 and z = 0.0, because it is at the origin of the turn and a point does not move when you turn around it.

The lights are still 1 away. The right light is at x = 0.5, z = -0.87 and the left light at x = -0.5, z = 0.87, and each of those is 1 from the middle. They have swung around the body the way the moon swung around the planet. If the loop rotated each part with no origin, every part would turn in place and the lights would stay where they were, beside a body that now points the other way.

Hinge question · from today's chunks

Before you build

Question: A student writes wheel.rotate(angle=5, axis=vec(0, 0, 1)) inside the loop and says the wheel spins far too fast and looks like it is jumping about. What is wrong with the angle, and what is the fix?

The angle has no radians around it, so 5 means 5 radians, which is 286 degrees, rounded to the nearest degree. The wheel turns almost all the way round on every pass, which looks like jumping.

The fix is angle=radians(5): 5 degrees per pass, 150 degrees a second. Every angle in a VPython program is written with radians around it.

The turn function for a model in a list

This is chunk 6's loop inside a bound function, with the angle chosen by the key. The function turns every part around the body's pos, so the lights swing with the body.

from vpython import *

ground = box(pos=vec(0, -0.1, 0), size=vec(40, 0.2, 40), color=color.green)
body = box(pos=vec(0, 0.5, 0), size=vec(2, 1, 1), color=color.red)
parts = [body]
parts.append(sphere(pos=vec(1, 0.5, 0.3), radius=0.2, color=color.yellow))
parts.append(sphere(pos=vec(1, 0.5, -0.3), radius=0.2, color=color.yellow))

def turn(evt):
    angle = 0
    if evt.key == "left":
        angle = radians(30)
    if evt.key == "right":
        angle = radians(-30)
    for part in parts:
        part.rotate(angle=angle, axis=vec(0, 1, 0), origin=body.pos)
    print(evt.key, "  body points along x =", round(body.axis.x, 2), " z =", round(body.axis.z, 2),
          "  first light at x =", round(parts[1].pos.x, 2), " z =", round(parts[1].pos.z, 2))

scene.bind("keydown", turn)

while True:
    rate(30)

Predict: Left is tapped twice, then right once. After the three taps, how far round has the car turned in total? Do the lights stay at the front of the car?

What it actually prints (run without a browser, quit after 6 passes of the loop)

left   body points along x = 1.73  z = -1.0   first light at x = 1.02  z = -0.24
left   body points along x = 1.0  z = -1.73   first light at x = 0.76  z = -0.72
right   body points along x = 1.73  z = -1.0   first light at x = 1.02  z = -0.24

Fed in by the build script: the left arrow key pressed on pass 2, the left arrow key pressed on pass 3, the right arrow key pressed on pass 5.

30 degrees to the left in total: two left taps make 60, and one right tap takes 30 back. The output box shows the body's axis going to 60 degrees and then back to 30.

The lights stay at the front. Each tap rotates every part around the body's pos, so a light that was 1 ahead of the body is still 1 ahead of it in the new direction. The last line shows the first light at x = 1.02, z = -0.24, which is in front of a body whose axis is x = 1.73, z = -1.0.

A tap of any other key sets no angle, so angle stays 0 and rotate does nothing. That is why the function can be bound to every key without a gate around the loop.

Running this in VS Code

Once, before the first run

Open the terminal in VS Code and install the library: pip install vpython. Check it worked with python -c "import vpython". It should print nothing at all and give you the prompt back. A traceback here is an install problem, not a problem with your program.

Every run after that

Save your file as YourName_vpython04.py: your first name, an underscore, then vpython04. Run it from the terminal. The 3D scene opens in a new browser tab, sometimes behind VS Code, so look for it before deciding that nothing happened. Click inside the scene before pressing any key. To end the program, close the tab or press Ctrl+C in the terminal. The program is written to run until you do. Run the file again and you get a fresh tab.
