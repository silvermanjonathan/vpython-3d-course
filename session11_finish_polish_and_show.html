Settings used on this page

Every shape and widget is made by naming its settings, like box(pos=vec(0, 0.5, 0), size=vec(2, 1, 1)). These are the ones the programs on this page use. The name before the = is the setting, and the value after it is what you give it.

SettingWhat it means
posWhere the shape is: three numbers, vec(x, y, z). x is right, y is up, z is toward you. For a box or a sphere, pos is the middle. For a cylinder, cone, or arrow, pos is the end the shape starts from, and it grows from there in the direction of its axis. For an arrow, pos is the tail.
sizeA box's three measurements, vec(long, tall, deep): along x, along y, along z. Each starts at 1 if you do not say.
radiusHow big round a sphere, cylinder, cone, or ring is: the distance from the middle to the edge. The lowest point is the radius below the middle.
colorcolor.red, color.gray(0.4), or vec(r, g, b) with each number from 0 to 1.
opacityHow see-through: 1 is solid, 0 is invisible, 0.5 is glass.
textThe words a label, button, or wtext shows.
heightFor a label: the size of its letters, in pixels.
boxFor a label: box=False takes away the frame drawn around its words.
bindThe name of the function to run when a key, click, or widget happens. The name alone, no brackets.

Chunk 1 of 3

A start screen: a title, and a key that begins

A program that starts moving the moment it opens gives the viewer no time to read the caption. Keep a state that starts as "start", show a title label, and gate everything that moves on state == "play". The space key, which arrives as the string " ", changes the state and hides the title. This is session 7's state name with one more value.

from vpython import *

scene.caption = "Press space to start. Arrow keys move the ball."
ground = box(pos=vec(0, -0.1, 0), size=vec(12, 0.2, 12), color=color.green)
ball = sphere(pos=vec(0, 0.5, 0), radius=0.5, color=color.yellow)
title = label(pos=vec(0, 3, 0), text="BALL RUN", height=30, box=False)
ground.state = "start"

def begin(evt):
    if evt.key == " " and ground.state == "start":
        ground.state = "play"
        title.visible = False
        print("space pressed: state is now", ground.state)

scene.bind("keydown", begin)
passes = 0

while True:
    rate(30)
    passes = passes + 1
    keys = keysdown()

    if ground.state == "play" and "right" in keys:
        ball.pos.x = ball.pos.x + 0.2

    if passes in [3, 6]:
        print("pass", passes, "  state", ground.state, "  ball at", ball.pos)

Predict: The right arrow is held on pass 2, before space is pressed, and again on passes 5 and 6, after it. Does the ball move on pass 2? Where is it on pass 6?

What it actually prints (run without a browser, quit after 6 passes of the loop)

pass 3   state start   ball at <0, 0.5, 0>
space pressed: state is now play
pass 6   state play   ball at <0.4, 0.5, 0>

Fed in by the build script: the right arrow key held on pass 2, the space key pressed on pass 4, the right arrow key held on passes 5 to 6.

No. On pass 2 the state is still start, so the gate ground.state == "play" and "right" in keys is False and the ball stays at x = 0; the pass 3 line shows that. After space on pass 4, the state is play, and the two held passes move the ball to x = 0.4 by pass 6.

The state lives on the ground, because the bound function and the loop both need it. The space key's name is a single space character, which is easy to miss when reading the program.

Chunk 2 of 3

Reset puts everything back, because every thing knows its home

A Reset that works has to know where everything started. Give each moving thing a home attribute holding a copy of its starting pos, made with vec(thing.pos.x, thing.pos.y, thing.pos.z). The Reset function loops over the list and puts each thing back at its home. Copying matters: thing.home = thing.pos would make home the same vector as the pos, and it would move with the thing.

from vpython import *

ground = box(pos=vec(0, -0.1, 0), size=vec(12, 0.2, 12), color=color.green)
things = []
things.append(box(pos=vec(0, 0.5, 0), color=color.orange))
things.append(sphere(pos=vec(3, 0.5, -2), radius=0.5, color=color.cyan))
for thing in things:
    thing.home = vec(thing.pos.x, thing.pos.y, thing.pos.z)

def reset(b):
    for thing in things:
        thing.pos = thing.home
        thing.visible = True
    print("reset: box at", things[0].pos, " ball at", things[1].pos)

button(text="Reset", bind=reset)
passes = 0

while True:
    rate(30)
    passes = passes + 1
    things[0].pos.x = things[0].pos.x + 0.5
    things[1].pos.z = things[1].pos.z + 0.5

    if passes == 4:
        print("pass 4: box at", things[0].pos, " ball at", things[1].pos, " box home is still", things[0].home)

Predict: The box and the ball move 0.5 on every pass. Reset is clicked on pass 6. Where are they after the click, and why is the box's home on pass 4 still <0, 0.5, 0> after four moves?

What it actually prints (run without a browser, quit after 8 passes of the loop)

pass 4: box at <2, 0.5, 0>  ball at <3, 0.5, 0>  box home is still <0, 0.5, 0>
reset: box at <0, 0.5, 0>  ball at <3, 0.5, -2>

Fed in by the build script: the widget bound to reset clicked on pass 6.

After the click the box is back at <0, 0.5, 0> and the ball at <3, 0.5, -2>, their starting places. The loop then moves them again from there.

The home is unchanged on pass 4 because it is a copy: a new vector built from the three numbers the pos had at the start. The moves change the pos and never touch the copy. Written as thing.home = thing.pos with no copy, the home would be the pos itself, and Reset would put each thing back exactly where it already was.

Chunk 3 of 3

Three lines of polish

scene.background is the colour behind everything. scene.title is a heading above the scene. Opacity on the ground lets a viewer see a thing that is behind it from a low camera. None of these change what the program does; all of them change what the viewer sees first.

from vpython import *

scene.title = "Ball Run, by Jonathan\n"
scene.background = vec(0.1, 0.1, 0.25)
ground = box(pos=vec(0, -0.1, 0), size=vec(12, 0.2, 12), color=color.green, opacity=0.8)
ball = sphere(pos=vec(0, 0.5, 0), radius=0.5, color=color.yellow)
print("title:", scene.title)
print("background:", scene.background, "  ground opacity:", ground.opacity)

Predict: What colour is vec(0.1, 0.1, 0.25): dark or light, and closer to blue or to red? Where does the title appear?

What it actually prints (run without a browser)

title: Ball Run, by Jonathan

background: <0.1, 0.1, 0.25>   ground opacity: 0.8

Dark, because all three numbers are small, and closer to blue, because the third number is the biggest of the three. A night sky. The title appears above the scene, in the tab, with its \n putting a blank line between it and the scene.

Keep the polish to lines like these. A feature added in the last ten minutes is where the demo breaks.

The partner test, 10 minutes

Swap seats with a neighbour. Do not explain your program. Your partner reads the caption, and only the caption, and tries every control it names. For each one they write a line on your expected-and-got sheet: what the caption said, what happened. Then swap back.

Three things a partner finds that an author does not: a control the caption names that does nothing, a key that does something the caption does not say, and a thing that can go wrong when the controls are used in an order the author never tried. Fix the first kind first.

The demo: two minutes, four sentences

Each demo is two minutes. Say these four things, in this order, then show one key and one click:

  1. What it is. One sentence: a game where you dodge falling blocks; a solar system with a moon; an editor for building a village.
  2. What it does when you use it. Name the controls as you show them: press space, hold right, click a block.
  3. One thing that was hard, and how you fixed it. The bug, the line, the fix.
  4. What you would add next. One feature, from your plan sheet.

Before your turn: the tab is open, the scene has been clicked so the keys work, and the program has been restarted so it is at its start screen. During your turn, if something breaks, say what you think it is and move on. A demo with a bug and a sentence about the bug is a complete demo.

Demo order and what the room does

The order is the order of the plan sheets on the desk, so nobody is first because of where they sit. While one person shows, everyone else writes one line on a slip: one thing the program did that they want to try in their own. The slips go to the author at the end.

The teacher keeps the time and says nothing about the program until all demos are done.

Hinge question · reaches back to session 1

Before you build

Question: From session 1: during a demo, a visitor presses the left arrow and nothing happens. Name the two things that could be true, and say how to check each one in five seconds.

One: the browser tab does not have the focus, so the key went to the editor or somewhere else. Check by clicking once inside the 3D scene and pressing the key again.

Two: the program has stopped. Check the terminal: if the prompt is back, the loop at the bottom is not running, because the program ended or an error stopped it, and the traceback above the prompt says which line. Run it again.

Build · 30 minutes

Build: finish, test, polish, show

Finish the features on your plan sheet, in the order the sheet says, one at a time. Then the start screen and the Reset from chunks 1 and 2, if your project needs them. Then the partner test. Then the three lines of polish. Then the demo.

  1. Make every control the caption promises work, or take it out of the caption.
  2. Add the start state and the space key if anything moves on its own, so the viewer can read the caption first.
  3. Add the Reset button with a home on every moving thing, or an r key if your numbers live in the loop.
  4. Partner test. Fix what the partner found, first kind first.
  5. Title, background, opacity. Nothing else new.
  6. Restart the program, click the scene, and leave it at the start screen for the demo.

Running this in VS Code

Once, before the first run

Open the terminal in VS Code and install the library: pip install vpython. Check it worked with python -c "import vpython". It should print nothing at all and give you the prompt back. A traceback here is an install problem, not a problem with your program.

Every run after that

Save your file as YourName_vpython11.py: your first name, an underscore, then vpython11. Run it from the terminal. The 3D scene opens in a new browser tab, sometimes behind VS Code, so look for it before deciding that nothing happened. Click inside the scene before pressing any key. To end the program, close the tab or press Ctrl+C in the terminal. The program is written to run until you do. Run the file again and you get a fresh tab.

VPython draws solid shapes that you can turn and zoom. Everything you print still goes to the terminal, and everything you draw goes to the browser tab. Words in the terminal, pictures in the tab.
