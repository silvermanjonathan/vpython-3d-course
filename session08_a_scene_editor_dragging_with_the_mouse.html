A scene editor: dragging with the mouse

mousedown, mousemove and mouseup, a grabbed object that follows the mouse across the floor, a menu that picks the shape, and a checkbox that turns a click into a delete

Length 90 minutes Ages 10 to 11 New 7 items

What is new today

mousedown, mousemove, mouseup, evt.press, an attribute that holds what is held, project onto the floor at a height, snap with round on drop, menu and m.selected, checkbox and c.checked.

Deliberately re-used: Session 1: click, scene.mouse.pick, the gate on None, project. Session 5: attributes that share a number between functions.

The shared thing here is an object, not a number: floor.held is the shape being dragged, or None. It is the same move as sun.factor in session 5. Say so when chunk 2 arrives, because three functions have to agree on what is held and students will reach for a plain variable.

Opener · 10 minutes

Retrieval: picks, None, and project

Paper first.

Question: Inside a click function, what does scene.mouse.pick hold when the click was on empty space, and what happens if the next line is thing.color = color.red?

None. The next line asks None for a colour and the program stops with an AttributeError. The gate if thing is None: has to come first.

Question: What does scene.mouse.project(normal=vec(0, 1, 0), point=vec(0, 0, 0)) give?

The point where the mouse's line of sight meets a flat plane that faces up and passes through the middle of the world: the place on the floor that the mouse is over.

Question: Three functions need to know the same thing. Where does the course keep it, and why not in a plain variable?

On an object, as an attribute, the way sun.factor was kept on the sun. A function cannot assign to a plain variable outside itself, but it can assign to an attribute of any object it can see.

Chunk 1 of 6

Three events make a drag

A click is a press and a release in one place. A drag is a press, some moves, and a release somewhere else, and VPython reports each part as its own event: mousedown, mousemove, mouseup. Bind one function to each.

mousemove happens every time the mouse moves, button or no button. evt.press is True on a move while the button is held, which is how a function can tell a drag from a wander.

from vpython import *

scene.caption = "Press on the box, move, and let go."
crate = box(pos=vec(0, 0.5, 0), color=color.orange)

def down(evt):
    print("mousedown   press is", evt.press)

def move(evt):
    print("mousemove   press is", evt.press)

def up(evt):
    print("mouseup     press is", evt.press)

scene.bind("mousedown", down)
scene.bind("mousemove", move)
scene.bind("mouseup", up)

while True:
    rate(30)

Predict: The mouse presses on the box, moves once, lets go, and then moves once more with no button down. Four events. For which of them is evt.press True?

What it actually prints (run without a browser, quit after 6 passes of the loop)

mousedown   press is True
mousemove   press is True
mouseup     press is False
mousemove   press is False

Fed in by the build script: the button pressed at (0, 0.5, 0) on pass 1, the mouse moved at (1, 0.5, 0) on pass 2, the button released at (1, 0.5, 0) on pass 3, the mouse moved at (2, 0.5, 0) on pass 5.

Only the first two. mousedown is a press, and the move right after it happens with the button still down, so both print True. mouseup is the release, and the last move happens with no button down, so both print False.

In a real run there would be many more mousemove lines, one for every small movement, which is why the next chunks only act on a move when something is held.

Chunk 2 of 6

Grab: remember what was pressed on

On mousedown, look at the pick. If it is a shape and not the floor, remember it in floor.held. The floor is the one object every function can see, so an attribute on it is where the three drag functions keep what they share. When nothing is held, floor.held is None.

from vpython import *

floor = box(pos=vec(0, -0.1, 0), size=vec(12, 0.2, 12), color=color.green)
floor.held = None
crate = box(pos=vec(2, 0.5, 0), color=color.orange)
ball = sphere(pos=vec(-2, 0.5, 0), radius=0.5, color=color.cyan)

def grab(evt):
    thing = scene.mouse.pick
    if thing is None or thing is floor:
        floor.held = None
        print("pressed on nothing to grab")
    else:
        floor.held = thing
        print("grabbed the thing at", floor.held.pos)

scene.bind("mousedown", grab)

while True:
    rate(30)

Predict: Three presses: on the crate, on an empty patch of floor, and on the ball. What does floor.held hold after each one?

What it actually prints (run without a browser, quit after 6 passes of the loop)

grabbed the thing at <2, 0.5, 0>
pressed on nothing to grab
grabbed the thing at <-2, 0.5, 0>

Fed in by the build script: the button pressed at (2, 0.5, 0) on pass 1, the button pressed at (0, 0, 3) on pass 3, the button pressed at (-2, 0.5, 0) on pass 5.

After the first press it holds the crate, and the print shows the crate's pos. After the second it holds None: the pick was the floor, and the gate treats the floor like empty space. After the third it holds the ball.

The gate uses or: either reason, None or the floor, means there is nothing to grab. Without the floor check, a press on the floor would grab the floor, and the next chunk would drag the whole ground around.

Chunk 3 of 6

Drag: move what is held to where the mouse is

On mousemove, if something is held, put it where the mouse is on the floor. project from session 1 finds that point, with one change: the plane is at height 0.5, point=vec(0, 0.5, 0), so the dragged shape's middle stays half a unit up and the shape slides along the floor instead of sinking into it.

from vpython import *

floor = box(pos=vec(0, -0.1, 0), size=vec(12, 0.2, 12), color=color.green)
floor.held = None
crate = box(pos=vec(2, 0.5, 0), color=color.orange)
scene.forward = vec(0, -0.6, -1)

def grab(evt):
    thing = scene.mouse.pick
    if thing is None or thing is floor:
        floor.held = None
    else:
        floor.held = thing

def drag(evt):
    if floor.held is not None:
        spot = scene.mouse.project(normal=vec(0, 1, 0), point=vec(0, 0.5, 0))
        floor.held.pos = spot
        print("dragged to", spot)

scene.bind("mousedown", grab)
scene.bind("mousemove", drag)

while True:
    rate(30)

Predict: The mouse presses on the crate and moves twice. After the second move, what is the crate's y, and why is it not 0?

What it actually prints (run without a browser, quit after 6 passes of the loop)

dragged to <2.8, 0.5, 1.1>
dragged to <3.6, 0.5, 2.3>

Fed in by the build script: the button pressed at (2, 0.5, 0) on pass 1, the mouse moved at (2.8, 0.5, 1.1) on pass 2, the mouse moved at (3.6, 0.5, 2.3) on pass 3.

The crate's y is 0.5 after every move. The plane that project uses passes through vec(0, 0.5, 0), so every point it gives has y = 0.5, and the crate's middle stays half a unit above the floor.

With point=vec(0, 0, 0) the crate's middle would be put on the floor itself, and half of it would be under the ground, the session 1 mistake made by the mouse instead of by a typed number.

Chunk 4 of 6

Drop: let go, and snap to the grid

On mouseup, if something is held, round its x and z to whole numbers so it lands on a grid, then set floor.held to None so moves stop dragging it. The crate's y does not need rounding, because the drag kept it at 0.5.

from vpython import *

floor = box(pos=vec(0, -0.1, 0), size=vec(12, 0.2, 12), color=color.green)
floor.held = None
crate = box(pos=vec(2, 0.5, 0), color=color.orange)
scene.forward = vec(0, -0.6, -1)

def grab(evt):
    thing = scene.mouse.pick
    if thing is None or thing is floor:
        floor.held = None
    else:
        floor.held = thing

def drag(evt):
    if floor.held is not None:
        floor.held.pos = scene.mouse.project(normal=vec(0, 1, 0), point=vec(0, 0.5, 0))

def drop(evt):
    if floor.held is not None:
        floor.held.pos = vec(round(floor.held.pos.x), 0.5, round(floor.held.pos.z))
        print("dropped at", floor.held.pos)
        floor.held = None

scene.bind("mousedown", grab)
scene.bind("mousemove", drag)
scene.bind("mouseup", drop)

while True:
    rate(30)

Predict: The crate is dragged to x = 3.6, z = 2.3 and dropped there. Where does it land? After the drop, the mouse moves again. Does the crate follow it?

What it actually prints (run without a browser, quit after 8 passes of the loop)

dropped at <4, 0.5, 2>

Fed in by the build script: the button pressed at (2, 0.5, 0) on pass 1, the mouse moved at (3.6, 0.5, 2.3) on pass 2, the button released at (3.6, 0.5, 2.3) on pass 3, the mouse moved at (-4, 0.5, -4) on pass 5.

It lands at <4, 0.5, 2>: 3.6 rounds to 4 and 2.3 rounds to 2.

The crate does not follow the later move. drop set floor.held to None, so the gate in drag is False and the move does nothing. That line is what ends a drag; without it, every move for the rest of the program would carry the crate along.

Chunk 5 of 6

A menu picks the shape, and a click on the floor makes one

A menu is a drop-down list under the scene. Its function gets the menu, and m.selected is the word that was chosen. The chosen shape is kept on the floor, as floor.tool, so the click function can read it.

A click on the floor makes the chosen shape at the clicked spot. A box's pos is its middle, so it goes at y = 0.5. A cone's pos is its flat end, so it goes at y = 0 and points up.

from vpython import *

floor = box(pos=vec(0, -0.1, 0), size=vec(12, 0.2, 12), color=color.green)
floor.tool = "box"
scene.forward = vec(0, -0.6, -1)

def pick_tool(m):
    floor.tool = m.selected
    print("tool is now", floor.tool)

menu(choices=["box", "ball", "cone"], bind=pick_tool)

def make(evt):
    if scene.mouse.pick is floor:
        spot = scene.mouse.project(normal=vec(0, 1, 0), point=vec(0, 0, 0))
        x = round(spot.x)
        z = round(spot.z)
        if floor.tool == "box":
            thing = box(pos=vec(x, 0.5, z), color=color.orange)
        if floor.tool == "ball":
            thing = sphere(pos=vec(x, 0.5, z), radius=0.5, color=color.cyan)
        if floor.tool == "cone":
            thing = cone(pos=vec(x, 0, z), axis=vec(0, 1, 0), radius=0.5, color=color.red)
        print("made a", floor.tool, "at", thing.pos)

scene.bind("click", make)

while True:
    rate(30)

Predict: A click on the floor, then the menu is set to cone, then two clicks at the same spot. What is made by each click, and why does the third click make nothing?

What it actually prints (run without a browser, quit after 8 passes of the loop)

made a box at <1, 0.5, 2>
tool is now cone
made a cone at <-3, 0, 1>

Fed in by the build script: a click at (1.2, 0, 1.8) on pass 1, the widget bound to pick_tool set to 2 on pass 3, a click at (-3.4, 0, 0.6) on pass 4, a click at (-3.4, 0, 0.6) on pass 6.

The first click makes a box at <1, 0.5, 2>, because the tool starts as box. The second makes a cone at <-3, 0, 1>: y is 0 for a cone, because its pos is its flat end.

The third click is on the same spot, where the cone now stands, so the pick is the cone and not the floor. The gate scene.mouse.pick is floor is False and nothing is made. A click on a shape is the next chunk's job.

Chunk 6 of 6

A checkbox turns a press into a delete

A checkbox is a tick box under the scene. Its function gets the checkbox, and c.checked is True while it is ticked. Keep it on the floor as floor.delete. In grab, a press on a shape while delete mode is on hides the shape instead of holding it.

from vpython import *

floor = box(pos=vec(0, -0.1, 0), size=vec(12, 0.2, 12), color=color.green)
floor.held = None
floor.delete = False
crate = box(pos=vec(2, 0.5, 0), color=color.orange)
ball = sphere(pos=vec(-2, 0.5, 0), radius=0.5, color=color.cyan)

def set_delete(c):
    floor.delete = c.checked
    print("delete mode is", floor.delete)

checkbox(text="Delete mode", bind=set_delete)

def grab(evt):
    thing = scene.mouse.pick
    if thing is None or thing is floor:
        floor.held = None
    elif floor.delete:
        thing.visible = False
        print("deleted the thing at", thing.pos)
    else:
        floor.held = thing
        print("grabbed the thing at", thing.pos)

scene.bind("mousedown", grab)

while True:
    rate(30)

Predict: A press on the crate, then the box is ticked, then two presses on the ball. What happens on each press? Why does the last press not delete anything?

What it actually prints (run without a browser, quit after 8 passes of the loop)

grabbed the thing at <2, 0.5, 0>
delete mode is True
deleted the thing at <-2, 0.5, 0>

Fed in by the build script: the button pressed at (2, 0.5, 0) on pass 1, the widget bound to set_delete set to True on pass 3, the button pressed at (-2, 0.5, 0) on pass 4, the button pressed at (-2, 0.5, 0) on pass 6.

The first press grabs the crate, because delete mode is off. The second press, after the tick, deletes the ball: it is hidden. The third press is on the same spot, but a hidden shape cannot be picked, so the pick is the floor and the first gate catches it. Nothing is deleted and nothing is grabbed.

elif is a second gate that is only checked when the first was False. Here it means: not nothing, and delete mode is on.

Hinge question · reaches back to session 1

Before you build

Question: From session 1: a student's dragged shape sinks half into the floor while it is being dragged, then pops up to the right height when it is dropped. Which line has the mistake, which argument in it, and what is the right value?

The project line inside drag. Its point argument is vec(0, 0, 0), so the plane the mouse is projected onto is the floor itself, and a box's middle is put on the floor. The right value is vec(0, 0.5, 0), half the box's height up.

The drop looks right because drop builds a new pos with 0.5 written in. The drag has to use the same height.

Build · 15 minutes

Build: the scene editor

An editor for building a scene with the mouse. A menu picks the shape and a second menu picks the colour. A click on the floor makes the chosen shape there. A press on a shape grabs it, moving the mouse drags it across the floor, and letting go drops it on the grid. A Delete mode checkbox turns a press into a delete. A line of text under the scene counts the shapes that are standing, and a Reset button hides them all.

  2. Add grab, drag and drop from chunks 2 to 4, with the delete gate from chunk 6 in grab.
  3. Add a wtext under the scene. After every make and every delete, count the shapes in the list whose visible is True, with a loop and a counter, and set the text to "Shapes: " + str(count).
  4. Add a Reset button whose function hides every shape in the list and sets the text to Shapes: 0.
  5. Write a caption that says what a click, a drag, and the tick box do.

Two menus, and a shape with the right height for its kind

The colour menu works like the shape menu: its function puts the chosen colour on the floor as floor.paint. Every shape made goes into a list so that the count and the Reset can reach it. A cone's pos is its flat end, so it sits at y = 0; a box and a ball have their middle at y = 0.5.

from vpython import *

floor = box(pos=vec(0, -0.1, 0), size=vec(12, 0.2, 12), color=color.green)
floor.tool = "box"
floor.paint = color.orange
shapes = []
scene.forward = vec(0, -0.6, -1)

def pick_tool(m):
    floor.tool = m.selected

def pick_paint(m):
    if m.selected == "orange":
        floor.paint = color.orange
    if m.selected == "cyan":
        floor.paint = color.cyan
    if m.selected == "white":
        floor.paint = color.white
    print("paint is now", floor.paint)

menu(choices=["box", "ball", "cone"], bind=pick_tool)
scene.append_to_caption("  ")
menu(choices=["orange", "cyan", "white"], bind=pick_paint)

def make(evt):
    if scene.mouse.pick is floor:
        spot = scene.mouse.project(normal=vec(0, 1, 0), point=vec(0, 0, 0))
        x = round(spot.x)
        z = round(spot.z)
        if floor.tool == "box":
            thing = box(pos=vec(x, 0.5, z), color=floor.paint)
        if floor.tool == "ball":
            thing = sphere(pos=vec(x, 0.5, z), radius=0.5, color=floor.paint)
        if floor.tool == "cone":
            thing = cone(pos=vec(x, 0, z), axis=vec(0, 1, 0), radius=0.5, color=floor.paint)
        shapes.append(thing)
        print("shape", len(shapes), "is a", floor.tool, "at", thing.pos, "coloured", thing.color)

scene.bind("click", make)

while True:
    rate(30)

Running this in VS Code

Once, before the first run

Open the terminal in VS Code and install the library: pip install vpython. Check it worked with python -c "import vpython". It should print nothing at all and give you the prompt back. A traceback here is an install problem, not a problem with your program.

Every run after that

Save your file as YourName_vpython08.py: your first name, an underscore, then vpython08. Run it from the terminal. The 3D scene opens in a new browser tab, sometimes behind VS Code, so look for it before deciding that nothing happened. Click inside the scene before pressing any key. To end the program, close the tab or press Ctrl+C in the terminal. The program is written to run until you do. Run the file again and you get a fresh tab.

VPython draws solid shapes that you can turn and zoom. Everything you print still goes to the terminal, and everything you draw goes to the browser tab. Words in the terminal, pictures in the tab.
